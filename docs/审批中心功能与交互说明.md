## 边界说明

- **审批中心**是**工作流平台**的**运行时前端入口**，不是独立的业务应用。
- 它聚合跨业务的待审批、已审批、抄送、我发起的审批事项，提供统一的审批操作体验（通过、驳回、转交、加签、评论、撤回、催办等）。
- 它**不配置**审批流程模板、流程节点、审批规则、条件分支、字段权限；流程建模统一由《流程设计器功能与交互说明.md》定义。
- 它**不管理**租户级用户、角色、组织架构、通用数据范围；这些由《后台设置功能与交互说明.md》定义。
- 业务应用通过《应用配置功能与交互说明.md》中的「流程绑定」能力，将工作流平台已发布的流程与本应用关联，审批中心负责运行时消费。
- 四个入口的完整边界关系详见《鑫渠基础平台职责边界说明.md》。

## 二、模块定位与目标

### 2.1 模块定位

审批中心是鑫渠 CRM **跨业务通用审批入口**，承担全系统所有需要人工决策流程的统一收口职责。它不替代各业务模块内部的专业审批逻辑（如意向管理的撞单裁决、设备投放的装机审批），而是将散落在各业务域的审批待办、审批历史、审批配置聚合到一个可统一操作、统一追踪、统一分析的入口。

### 2.2 解决的核心问题

- **审批入口分散**：销售、经理、财务、法务、厂家负责人需要在多个模块之间切换才能处理全部待审批事项。
- **审批进度不透明**：发起人难以实时掌握单据流转到哪个节点、被谁卡住、预计何时完成。
- **审批标准不一致**：不同业务的审批弹窗、必填项、操作按钮各异，增加学习成本与误操作风险。
- **审批时效难追踪**：管理层无法量化审批耗时、驳回率、节点滞留时长，难以优化流程。
- **历史记录查询困难**：审批记录散落在各业务详情页，无法按人、按业务、按时间维度统一检索。

### 2.3 带来的业务价值

| 价值点 | 说明 |
|---|---|
| 一站处理 | 所有待审批、已审批、抄送我的事项集中展示，减少页面跳转 |
| 流程可视 | 审批链路、当前节点、历史意见、预计下一节点一目了然 |
| 体验统一 | 统一的审批操作组件、统一的必填校验、统一的反馈提示 |
| 效率可量化 | 提供审批时效、节点耗时、驳回率、超时率等核心指标 |
| 风险可控 | 支持加签、转交、撤回、挂起等异常处理机制，防止流程僵死 |
| 审计留痕 | 所有审批行为、意见、附件、操作人、时间永久留存 |

## 三、业务场景与角色

### 3.1 使用角色

| 角色 | 核心诉求 | 典型操作 |
|---|---|---|
| **发起人** | 提交申请后想知道审批进度与结果 | 提交、查看进度、撤回、查看驳回原因、重新发起 |
| **审批人** | 快速处理分配给自己的待审批事项 | 通过、驳回、转交、加签、填写意见、批量审批 |
| **抄送人** | 及时获知相关审批结果，便于协同 | 查看审批动态、接收抄送通知、查阅历史 |
| **代理人** | 在原审批人休假/出差时代为处理 | 代审批、代查看、权限到期自动回收 |
| **流程管理员** | 处理流程异常、设置代理人、监控流程实例 | 强制转交、流程监控、跳转流程设计器进行模板/节点配置 |
| **管理层** | 关注审批效率与瓶颈 | 查看审批时效报表、节点耗时分析、超时预警 |

### 3.2 典型业务场景

| 场景编号 | 场景名称 | 触发业务 | 参与角色 | 场景描述（谁 + 在什么情况下 + 做什么 + 达成什么） |
|---|---|---|---|---|
| S1 | 意向报备提交后等待上级领导初审 | 意向管理 | 发起人、上级领导 | 销售代表在客户意向确定后，通过系统提交意向报备申请，由上级领导在审批中心初审通过，使意向进入有效保护期 |
| S2 | 撞单冲突触发双人并行裁决 | 意向管理 | 厂家经理、厂家负责人 | 多名销售代表同时报备同一客户/项目时，系统触发撞单审批，由厂家经理与厂家负责人并行裁决，确定唯一归属销售 |
| S3 | 招标项目申请厂家授权审批 | 意向管理 | 报单人、厂家经理 | 销售代表在投标前申请厂家项目授权，厂家经理在审批中心审核资质与范围，审批通过后销售获得正式授权参与投标 |
| S4 | 设备投放/回收协议审批 | 设备管理 | 销售、商务、法务、厂家负责人 | 销售代表与客户达成设备投放或回收意向后，提交协议审批，经商务、法务、厂家负责人逐级审批，确保协议合规并更新设备状态 |
| S5 | 特价/折扣申请审批 | 报价/订单 | 销售、销售经理、厂家经理、财务 | 销售代表面对大客户或竞争项目时申请特价/折扣，经销售经理、厂家经理、财务审批，确保价格政策受控并生成有效报价 |
| S6 | 市场活动费用报销审批 | 费用管理 | 申请人、部门经理、财务、总经理 | 市场人员完成市场活动后提交费用报销，部门经理、财务、总经理按金额与政策审批，确保费用合规并完成付款 |
| S7 | 客户退货/换货审批 | 售后/商务 | 销售、售后主管、商务、财务 | 客户提出退货/换货需求后，售后主管核实设备/试剂状况并提交审批，经商务、财务确认后执行退换货并更新库存 |
| S8 | 试剂价格调整审批 | 试剂运营 | 商务、厂家经理、财务 | 商务人员根据厂家调价通知或促销策略申请试剂价格调整，经厂家经理与财务审批后同步至报价与订单系统 |
| S9 | 客户授信/账期调整审批 | 客户管理 | 销售、财务、风控 | 销售人员基于客户合作历史申请授信额度或账期调整，财务与风控审批通过后更新客户信用档案与订单账期规则 |

## 五、业务流程

### 5.1 通用审批主流程

```
业务模块发起审批
        │
        ▼
系统根据业务类型匹配审批模板
        │
        ▼
生成审批实例，推送待办给第一个节点审批人
        │
        ▼
审批人查看审批详情
        │
        ├──── 通过 ────→ 进入下一节点 / 流程结束
        │
        ├──── 驳回 ────→ 退回发起人或上一节点
        │
        ├──── 转交 ────→ 指定新的审批人处理
        │
        ├──── 加签 ────→ 插入临时审批节点
        │
        └──── 评论 ────→ 仅记录意见，不流转
        │
        ▼
流程结束后通知发起人、抄送人
        │
        ▼
审批结果回写业务模块，驱动业务状态变更
```

### 5.2 待我审批处理流程

```
用户进入审批中心
        │
        ▼
默认展示「待我审批」Tab
        │
        ▼
查看待审批列表（按紧急程度/提交时间排序）
        │
        ▼
点击单据进入审批详情弹窗
        │
        ▼
查看业务信息、审批历史、当前节点说明
        │
        ▼
选择操作：通过 / 驳回 / 转交 / 加签 / 评论
        │
        ▼
填写审批意见（通过可简短，驳回必填详细原因）
        │
        ▼
提交后系统校验 → 更新流程状态 → 通知相关人
```

### 5.3 发起人追踪与撤回流程

```
用户进入「我发起的」Tab
        │
        ▼
查看所有发起单据及当前状态
        │
        ▼
点击单据进入详情
        │
        ▼
查看流程进度条 / 时间线
        │
        ├──── 当前节点未处理 ────→ 显示「撤回」按钮
        │                                │
        │                                ▼
        │                         撤回成功，单据状态变为「已撤回」
        │                                │
        │                                ▼
        │                         可重新编辑后再次发起
        │
        ├──── 已被驳回 ────→ 显示「重新发起」按钮
        │                        │
        │                        ▼
        │                 打开原单编辑页，预填所有字段
        │                        │
        │                        ▼
        │                 修改后重新提交，生成新审批实例
        │
        └──── 已通过 / 已结束 ────→ 仅查看，不可修改
```

### 5.4 代理人审批流程

```
审批人设置代理人（开始时间、结束时间、代理范围）
        │
        ▼
在代理有效期内，原审批人的待办自动转给代理人
        │
        ▼
代理人收到「代审批」标识的待办通知
        │
        ▼
代理人执行通过/驳回/转交等操作
        │
        ▼
审批记录中同时记录代理人与被代理人
        │
        ▼
代理到期后，未处理单据自动回到原审批人
```

### 5.5 统一状态流转表

| 当前状态 | 触发条件 / 操作 | 下一状态 | 通知对象 |
|---|---|---|---|
| 待审批 | 审批人点击「通过」（非末节点） | 审批中 | 发起人、下一节点审批人、抄送人 |
| 待审批 | 审批人点击「通过」（末节点） | 已通过 | 发起人、抄送人 |
| 待审批 | 审批人点击「驳回」 | 已驳回 | 发起人、上一节点审批人（如配置） |
| 待审批 | 审批人点击「转交」 | 已转交 → 待审批（新审批人） | 新审批人、原审批人、发起人 |
| 待审批 | 审批人点击「加签」 | 审批中（插入加签节点） | 加签人、原审批人、发起人 |
| 审批中 | 当前节点为会签，全部审批人通过 | 下一节点 / 已通过 | 发起人、下一节点审批人、抄送人 |
| 审批中 | 当前节点为或签，任一审批人通过 | 下一节点 / 已通过 | 发起人、下一节点审批人、抄送人 |
| 审批中 | 审批人点击「挂起」 | 已挂起 | 发起人、流程管理员 |
| 已挂起 | 管理员点击「恢复」 | 审批中 / 待审批 | 当前节点审批人、发起人 |
| 审批中 | 发起人点击「撤回」（下一节点未处理） | 已撤回 | 发起人 |
| 已驳回 | 发起人点击「重新发起」 | 待审批（新审批实例） | 新实例审批人 |
| 待审批 | 节点超时，系统按超时规则自动处理 | 已通过 / 已驳回 / 已转交 | 发起人、当前节点审批人、管理员 |
| 已通过 / 已驳回 / 已撤回 | 流程结束，无后续操作 | - | 抄送人、相关系统 |

#### 6.1.3 页面布局设计理念（五层架构）

本页面采用自顶向下、逐层聚焦的五层架构，布局图、下表与组件清单严格保持同一顺序：

| 层级 | 板块 | 用户心理 | 主要组件 |
|---|---|---|---|
| 第一层 | 顶部标题栏 + Tab 导航 | 「我要处理哪一类审批事项？」 | 页面标题、设置入口、Tab 标签组 |
| 第二层 | 统计卡片 | 「当前各类审批的数量与效率如何？」 | 待审 / 已处理 / 发起 / 抄送数量、平均耗时 |
| 第三层 | 快捷筛选 / 视图切换 / 批量操作 | 「我要优先看哪些？用什么视图？能否批量处理？」 | 全部/紧急/即将超时/超期筛选、列表/卡片切换、批量操作下拉 |
| 第四层 | 搜索 / 筛选器 | 「怎么快速定位目标单据？」 | 搜索框、业务类型/状态/时间下拉筛选 |
| 第五层 | 审批列表 / 卡片 + 分页 | 「具体有哪些单据需要处理？」 | 数据表格 / 卡片网格、分页组件 |

##### 1. 以「审批视角」而非「业务视角」组织信息

审批人不关心业务模块的分类边界，只关心「有哪些事要我决策」。因此顶部 Tab 按「与我相关的审批角色」划分：待我审批、我已审批、我发起的、抄送我的，而不是按业务类型划分。

##### 2. 突出 urgency

审批的核心是时效。统计卡片与快捷筛选中均突出「紧急」「即将超时」「已超期」三类状态，让用户一眼看到需要先处理的事项。

##### 3. 兼顾决策概览与批量效率

- **卡片视图**：展示单据标题、业务类型、申请人、当前节点、停留时长、状态标签，适合少量待审时快速概览。
- **列表视图**：字段更全、密度更高，支持多选批量操作，适合审批量大时集中处理。

默认规则：待审批总数 ≤20 时默认卡片视图，>20 时默认列表视图。

##### 4. 行动导向

每一行/卡片都提供明确的下一步操作入口：审批、查看、催办、转交。避免用户进入详情后才发现没有操作权限。

##### 7. 这样的设计解决了什么问题

| 问题 | 解法 |
|---|---|
| 审批入口分散，切换成本高 | 统一入口聚合所有业务审批 |
| 不知道哪些审批最紧急 | 统计卡片 + 紧急/即将超时/超期快捷筛选 |
| 审批量大时效率低 | 列表视图 + 批量操作 |
| 审批历史查询困难 | 按角色分类的列表 + 多维度筛选 |
| 审批进度不透明 | 流程进度条 + 审批时间线 |
| 审批操作体验不一致 | 统一审批弹窗、统一必填校验、统一反馈 |

##### 8. 后续可优化方向

- 列表视图支持表头排序（按提交时间、停留时长、金额）
- 支持自定义审批常用语，快速填写审批意见
- 增加审批语音输入（移动端）
- 待审事项支持一键全部已读
- 审批分析增加节点耗时热力图
- 支持审批单收藏 / 置顶

#### 6.2.3 布局说明

- **左侧业务信息**：按业务模块动态渲染，只读展示。复杂业务可折叠分组。
- **右侧审批区**：当前节点审批人可见操作按钮；非当前节点人员仅查看。

## 八、交互设计要点

### 8.1 搜索与筛选

| 筛选维度 | 适用 Tab | 说明 |
|---|---|---|
| 单据编号 | 全部 | 精确或模糊搜索 |
| 客户名称 | 全部 | 按关联业务单据中的客户搜索 |
| 申请人 | 全部 | 按申请人搜索 |
| 业务类型 | 全部 | 特价审批、意向报备、费用报销等 |
| 审批状态 | 我发起的 / 抄送我的 | 待审批 / 已通过 / 已驳回 / 已撤回 |
| 提交时间 | 全部 | 今天 / 近 7 天 / 近 30 天 / 自定义 |
| 停留时长 | 待我审批 | 即将超时 / 已超时 |
| 优先级 | 待我审批 | 普通 / 紧急 |

**交互规则**：
- 搜索输入支持回车触发与防抖自动搜索。
- 筛选条件改变后实时刷新列表，并自动重置到第 1 页。
- 切换 Tab 时保留上一次该 Tab 的筛选条件（可配置是否重置）。
- 支持「清空筛选」一键恢复默认。

### 8.2 视图切换

- 提供「列表视图」与「卡片视图」切换按钮。
- 列表视图每页 12 条，卡片视图每页 8 条。
- 切换视图、切换 Tab、执行筛选后，自动重置到第 1 页。
- 用户最近一次选择的视图保存在本地缓存中，下次进入默认使用。

### 8.3 操作反馈

| 操作 | 反馈方式 | 说明 |
|---|---|---|
| 通过 | Toast 成功提示 + 列表移除 | 提示「已通过」并展示下一节点 |
| 驳回 | Toast 成功提示 + 列表移除 | 提示「已驳回，已通知发起人」 |
| 转交 | Toast 成功提示 + 列表移除 | 提示「已转交给 XXX」 |
| 加签 | Toast 成功提示 + 列表保留 | 提示「已加签，等待加签人处理」 |
| 评论 | Toast 成功提示 | 提示「评论已保存」，时间线实时追加 |
| 批量操作 | 二次确认弹窗 + 结果反馈 | 显示成功/失败数量 |
| 提交失败 | 错误提示 + 保留表单 | 网络异常时允许重试 |
| 无权限 | 禁用操作按钮 + Tooltip | 提示「当前节点无需您审批」 |

### 8.4 空态设计

| 空态场景 | 文案 | 引导动作 |
|---|---|---|
| 待我审批为空 | 「暂无待审事项，您已处理完毕」 | 返回工作台 |
| 我已审批为空 | 「您还没有处理过审批单」 | 查看待我审批 |
| 我发起的为空 | 「您尚未发起任何审批」 | 跳转业务模块发起 |
| 抄送我的为空 | 「暂时没有抄送给您的审批单」 | - |
| 筛选结果为空 | 「未找到符合条件的审批单」 | 清空筛选 |
| 网络异常 | 「加载失败，请稍后重试」 | 点击刷新 |

### 8.5 审批意见输入

- **通过**：审批意见默认非必填，但建议填写。可配置某些业务类型强制要求。
- **驳回**：审批意见必填，至少 5 个字。未填写时按钮禁用并红字提示。
- **转交/加签**：原因必填。
- **评论**：内容必填，最多 500 字。
- 支持常用语快捷选择（如「同意」「请补充附件」「预算超标，请说明」）。
- 移动端支持语音输入转文本。

### 8.6 流程进度条

- 横向展示所有节点，节点名称下方显示审批人/处理时间。
- 当前节点高亮并显示「进行中」动效。
- 已通过节点显示绿色对勾 + 通过时间。
- 被驳回节点显示红色叉 + 驳回意见（可点击展开）。
- 未到达节点置灰。
- 会签节点显示多人头像，全部通过后才进入下一节点。

### 8.7 批量操作

- 列表视图支持多选框，卡片视图暂不支持批量。
- 批量操作仅对「相同业务类型 + 相同当前节点 + 当前用户有审批权限」的单据生效。
- 批量通过/驳回需统一填写一次审批意见。
- 批量操作前二次确认：「您选择了 5 条特价审批单，确认全部通过吗？」
- 批量操作后显示结果：「成功 4 条，失败 1 条，失败原因：XXX」。

### 8.8 异常交互规则

#### 8.8.1 表单校验错误

| 校验场景 | 校验规则 | 错误反馈 | 交互处理 |
|---|---|---|---|
| 审批意见长度 | 驳回/转交/加签意见必填，5–500 字；评论 1–500 字 | 输入框下方红字提示，提交按钮禁用 | 保留已输入内容，定位到首个错误字段 |
| 必填字段缺失 | 业务表单必填项未填写 | 表单项标红并提示「请填写 XXX」 | 滚动至缺失字段，阻止提交 |
| 附件格式/大小 | 仅支持 pdf/doc/docx/xlsx/png/jpg，单文件 ≤ 20MB | Toast 提示「附件格式不支持 / 超出大小限制」 | 阻止上传，允许重新选择 |
| 转交/加签目标人 | 必须选择有效用户，且不能是当前审批人或自己 | 提示「请选择有效转交人」 | 清空选择并保留原因字段 |
| 批量操作选择 | 必须选择同业务类型、同节点、有权限的单据 | 提示「请选择相同业务类型和节点的单据」 | 取消不符合项的选中状态 |

#### 8.8.2 并发审批冲突处理

| 冲突场景 | 系统行为 | 前端反馈 |
|---|---|---|
| 多人同时审批同一节点（会签/或签） | 工作流引擎对流程实例加乐观锁；首个提交成功后，其他提交收到版本冲突 | 提交者 1 显示「已通过」；提交者 2 弹窗提示「该节点已被处理，请刷新列表」 |
| 审批人点击通过时发起人恰好撤回 | 后端校验流程状态；若状态已变，则拒绝本次操作 | 提示「单据状态已变更，操作失败，请刷新后重试」 |
| 管理员强制转交/驳回时审批人正在操作 | 以管理员操作优先，审批人提交时校验当前待办人身份 | 提示「您已不是当前节点审批人，无法操作」 |
| 批量操作中有单据被他人处理 | 批量接口返回部分成功/失败明细 | Toast + 结果弹窗展示成功 N 条、失败 M 条及原因 |

#### 8.8.3 网络与系统异常

| 异常场景 | 系统行为 | 前端反馈 |
|---|---|---|
| 网络超时 | 提交请求未在 10 秒内返回 | 显示「网络超时，请稍后重试」并提供重试按钮 |
| 服务端 500 | 操作失败，流程状态不变 | Toast 提示「系统繁忙，请稍后重试」 |
| 权限不足 | 后端鉴权失败 | 禁用操作按钮并提示「您无权限执行此操作」 |
| 工作流引擎异常 | 记录失败日志，流程状态保持原状 | 提示「流程处理失败，请联系管理员」 |

## 十、核心设计原则与要点

| 原则 | 说明 |
|---|---|
| **统一入口，分域处理** | 审批中心聚合入口，但具体业务逻辑仍由各自业务域负责，避免审批中心过度膨胀 |
| **流程与表单解耦** | 审批中心只负责流程流转与通用字段，业务表单由各业务模块提供渲染 |
| **一处一决策** | 每个审批节点只呈现一个核心决策区，减少认知负担 |
| **审批意见强制留痕** | 驳回、转交、加签等关键操作必须填写意见，保证可追溯 |
| **时效优先** | 列表排序、统计卡片、快捷筛选均围绕审批时效设计 |
| **权限最小化** | 用户只能看到与操作自己相关的审批单，防止越权 |
| **异常可干预** | 提供转交、加签、挂起、强制通过/驳回等机制，防止流程僵死 |
| **结果回写业务** | 审批结束后，结果必须同步回业务模块，驱动业务状态变更 |
| **移动端一致体验** | 核心审批操作必须在企业微信/小程序可用 |
| **审批数据可分析** | 审批时效、驳回率、超时率等数据汇入经营驾驶舱 |

## 十二、未考虑到的问题补充（开发者视角）

以下问题在实际开发中容易被忽略，需重点关注：

| 问题类别 | 具体说明 |
|---|---|
| **并发审批** | 多人同时审批同一节点时，需加锁或乐观锁控制，避免重复流转 |
| **会签/或签的语义** | 会签需全部通过；或签任一通过即进入下一节点，但需明确「第一个通过后其他人是否还能处理」 |
| **驳回后的重新提交** | 重新发起是基于原单修改还是生成新单？建议生成新审批实例但保留原单关联 |
| **审批模板的版本管理** | 旧流程实例应继续使用旧版模板，新流程使用新版模板，避免运行中流程被模板变更影响 |
| **代理人循环委托** | A 委托 B，B 又委托 C 时需检测循环，防止无限委托 |
| **节假日与工作日的超时计算** | 超时规则是否排除节假日？需配置工作日历 |
| **审批附件的权限隔离** | 审批过程中上传的附件，哪些角色在流程结束后仍可查看 |
| **消息通知的防打扰** | 同一审批单多次催办时，避免频繁推送通知 |
| **审批历史的数据归档** | 审批记录量大后需考虑分表、归档策略，避免影响列表查询性能 |
| **跨业务字段差异** | 不同业务类型的审批单字段差异大，需设计灵活的表单渲染机制 |
| **审批撤回的条件** | 下一节点已开始处理或已会签通过一部分时，是否允许撤回 |
| **强制操作的审计** | 管理员强制通过/驳回需记录额外审计日志，并通知原审批人 |
| **移动端详情展示** | 复杂业务表单在移动端需重新设计布局，避免信息过载 |
| **审批分析的实时性** | 审批时效统计采用实时计算还是 T+1 离线计算，需根据数据量评估 |
| **第三方系统集成** | 若审批结果需同步 ERP/OA/财务系统，需考虑异步消息与补偿机制 |
| **审批人离职/调岗** | 审批人账号失效时，待审单据如何自动转交或提醒管理员 |
| **测试数据与流程覆盖** | 需提供丰富的测试用例覆盖通过、驳回、转交、加签、会签、超时、代理人等场景 |
