## 二、模块定位与目标

### 2.1 模块定位

品牌库管理是鑫渠 CRM **业务管理域**的**产品主数据中心**。它以 IVD 品牌、厂家、产品线、型号、注册证、试剂/耗材为核心对象，构建统一、标准、可信的产品主数据体系，并作为**跨应用复用**的唯一权威来源，向线索管理、意向报备、客户 360度、设备管理、试剂运营、售后工单、目标绩效等模块提供数据支撑。

> **核心定位一句话**：品牌库不是简单的「产品名录」，而是支撑全系统业务单据一致性的**主数据底座**。

### 2.2 解决的核心问题

| 问题 | 说明 |
|---|---|
| **一物多码** | 同一品牌/型号在不同业务模块中被录入成不同名称、不同编码，导致统计口径混乱。 |
| **数据重复录入** | 销售在报备、建设备、录试剂时重复填写品牌、型号、规格等基础信息，效率低且易错。 |
| **主数据不一致** | 意向管理里叫「希森美康 XN-550」，设备管理里叫「Sysmex XN550」，经营驾驶舱无法汇总。 |
| **注册证信息缺失** | IVD 产品受监管严格，缺少注册证号、有效期、生产企业信息会带来合规风险。 |
| **新品上线慢** | 新产品、新型号上线依赖开发改枚举或代码，无法由业务人员自主维护。 |
| **跨模块引用困难** | 各业务模块各自维护产品字典，难以形成客户视角的完整产品图谱。 |

### 2.3 带来的业务价值（含可量化指标）

| 价值维度 | 说明 | 可量化指标（目标值） |
|---|---|---|
| **数据统一** | 建立唯一的品牌/型号主数据标识，确保各模块引用同一份数据。 | 产品主数据重复率从 >15% 降至 <1%；跨模块同一型号名称不一致问题数降至 0。 |
| **效率提升** | 业务人员在录单时通过搜索/选择即可带出完整产品信息，减少重复录入。 | 意向报备/设备建档录单耗时平均降低 40% 以上；品牌/型号字段录入错误率降低 60% 以上。 |
| **合规可控** | 集中管理注册证、生产企业、有效期等监管字段，支持到期预警。 | 注册证到期漏处理率 0%；到期前 30 天预警覆盖率 100%。 |
| **分析准确** | 为经营驾驶舱、目标绩效、试剂消耗分析提供统一的产品维度口径。 | 品牌/型号维度报表汇总准确率达 99.5% 以上；经营分析准备时间缩短 50%。 |
| **扩展灵活** | 产品运营/管理员可自助新增、编辑、上下线品牌和型号，降低对研发的依赖。 | 新品/新型号上线周期从平均 3-5 天缩短至 <1 天；非研发人员发起的标准主数据变更占比 >=80%。 |

## 三、业务场景与角色

### 3.1 使用角色

| 角色 | 核心职责 | 系统操作 |
|---|---|---|
| **产品运营** | 维护品牌、产品线、型号、注册证等主数据，保证数据完整、准确、合规 | 新建、编辑、启用/禁用、批量导入、注册证管理 |
| **系统管理员** | 配置品牌库基础规则、审批流、数据权限、码规则 | 规则配置、权限分配、数据治理 |
| **销售代表** | 在业务单据中引用品牌库数据，反馈数据缺失/错误 | 搜索选择、申请新增、纠错反馈 |
| **销售经理** | 审核下属提交的新品/新型号申请，确保业务合理性 | 审批、查看品牌使用情况 |
| **商务运营** | 基于品牌库进行试剂、耗材、设备的主数据核对与对账 | 查看、导出、核对注册证 |
| **渠道管理员** | 维护经销商代理品牌范围，控制渠道可见品牌 | 配置品牌授权范围、查看渠道引用 |

### 3.2 典型业务场景

| 场景 | 参与角色 | 场景描述 |
|---|---|---|
| **新品上线** | 产品运营、销售经理 | 厂家发布新型号，产品运营在品牌库录入品牌、产品线、型号、注册证，销售经理审核后全业务模块可用。 |
| **意向报备选品** | 销售代表 | 报备意向时搜索品牌/型号，系统自动带出生产企业、注册证、规格，避免手工填写。 |
| **设备档案建档** | 销售代表/商务运营 | 创建设备档案时从品牌库选择型号，关联设备全生命周期数据。 |
| **试剂消耗对账** | 商务运营 | 按品牌、型号维度汇总试剂消耗，统一口径与厂家/经销商对账。 |
| **注册证到期预警** | 产品运营、合规专员 | 系统自动扫描即将到期的注册证，推送预警给相关人员，避免合规风险。 |
| **渠道品牌授权** | 渠道管理员 | 为经销商配置可代理的品牌范围，控制其在线索、意向中可见可选的品牌。 |
| **主数据纠错** | 销售代表、产品运营 | 销售发现型号名称/规格错误，提交纠错申请，产品运营核实后修正，自动同步到所有引用单据。 |

## 五、核心业务流程

### 5.1 品牌/型号主数据新建与审批流程

```
产品运营/销售代表发起新建
        │
        v
填写品牌/产品线/型号/注册证信息
        │
        v
系统校验：编码唯一、名称唯一、注册证有效
        │
        ├── 校验不通过 → 返回修改，提示冲突项
        │
        └── 校验通过 → 提交审批（销售经理/产品运营审核）
                    │
                    ├── 驳回 → 退回申请人，状态为「被驳回」
                    │
                    └── 通过 → 状态变为「已启用」，全模块可引用
```

**关键说明**：
- 新建品牌时自动生成品牌编码，编码规则由管理员配置（如 `BR-{厂家码}-{序号}`）。
- 型号名称与规格组合必须唯一，防止「XN-550」与「XN550」重复。
- 若已存在相似名称，系统给出「合并到现有数据 / 确认新建」的提示。
- 审批通过后，品牌/型号立即进入全局搜索与级联选择器。

### 5.2 业务单据引用品牌库流程

```
销售代表进入意向报备/设备建档/试剂录入页面
        │
        v
点击「选择品牌/型号」
        │
        v
弹出品牌库选择器（搜索 + 级联选择）
        │
        v
选择品牌 → 产品线 → 型号
        │
        v
系统自动带出：生产企业、注册证号、规格、单位、图片
        │
        v
业务单据保存时仅保存品牌库主键 + 快照字段
        │
        v
后续主数据更新时，业务单据可选择「同步最新数据」或保留历史快照
```

**关键说明**：
- 引用时保存主键（如 `brand_id`、`model_id`）+ 冗余快照（名称、规格、注册证号），保证查询性能与历史可追溯。
- 当主数据变更时，系统提示「N 条历史单据引用了该数据，是否同步更新快照」。
- 已被禁用的品牌/型号在引用选择器中置灰不可选，但历史单据仍可正常显示。

### 5.3 主数据变更与同步流程

```
产品运营发现型号信息需要修正
        │
        v
编辑型号字段（名称、规格、注册证等）
        │
        v
系统校验：是否影响历史单据
        │
        ├── 无影响 → 直接保存，变更生效
        │
        └── 有影响 → 提示影响范围（引用数量、关联模块）
                    │
                    ├── 仅修改主数据，不刷新历史单据快照
                    ├── 同步刷新所有历史单据快照
                    └── 提交变更审批（重大变更）
```

**关键说明**：
- 普通字段修改（如图片、简介）可直接生效。
- 关键字段修改（如型号名称、规格、注册证号）需评估影响范围，必要时走变更审批。
- 所有变更写入操作日志，记录变更前/变更后值、变更人、变更时间。

### 5.4 品牌/型号状态流转矩阵

品牌与型号共用同一套生命周期状态，流转规则如下：

| 当前状态 | 触发条件/操作 | 下一状态 | 允许操作人 | 通知对象 |
|---|---|---|---|---|
| 待审批 | 产品运营/销售经理审批通过 | 已启用 | 产品运营、销售经理、系统管理员 | 申请人、相关模块管理员 |
| 待审批 | 审批人驳回 | 被驳回 | 产品运营、销售经理、系统管理员 | 申请人 |
| 已启用 | 操作「禁用」并二次确认 | 已禁用 | 产品运营、系统管理员 | — |
| 已启用 | 编辑关键字段并提交变更审批 | 待审批 | 产品运营、系统管理员 | 审批人 |
| 已禁用 | 操作「启用」并二次确认 | 已启用 | 产品运营、系统管理员 | — |
| 被驳回 | 申请人修改后重新提交 | 待审批 | 申请人、产品运营 | 审批人 |
| 被驳回 | 申请人放弃/撤销 | 已禁用 | 申请人、产品运营 | — |

**状态说明**：
| 状态 | 含义 | 业务影响 |
|---|---|---|
| 待审批 | 新建或重大变更已提交，等待审核 | 未生效，不可在业务单据中引用 |
| 已启用 | 审批通过，正式生效 | 可在各业务模块中搜索、选择、引用 |
| 已禁用 | 被主动禁用或审批被废弃 | 历史单据正常显示，新业务单据不可引用；选择器中置灰 |
| 被驳回 | 审批未通过，需修改后重新提交 | 不可引用，申请人可见驳回原因 |

```
                    ┌─────────────┐
                    │   待审批    │
                    └──────┬──────┘
           ┌───────────────┼───────────────┐
           v               v               v
      ┌─────────┐    ┌─────────┐    ┌─────────┐
      │ 被驳回  │    │ 已启用  │    │ 已禁用  │
      └────┬────┘    └────┬────┘    └────┬────┘
           │              │              │
           └──────┬───────┘              │
                  v                       │
             重新提交                    启用
                  │                       │
                  └───────────────────────┘
```

## 八、交互设计要点

### 8.1 搜索筛选

| 搜索/筛选项 | 说明 |
|---|---|
| 关键字搜索 | 支持按品牌名称、型号名称、厂家名称、注册证号模糊搜索 |
| 产品线筛选 | 多选下拉，支持「仪器 / 试剂 / 耗材 / 整体解决方案」 |
| 状态筛选 | 全部 / 已启用 / 已禁用 / 待审批 / 被驳回 |
| 注册证状态筛选 | 全部有效 / 即将到期 / 已过期 / 未上传 |
| 厂家筛选 | 按所属厂家过滤 |
| 筛选结果 | 实时更新，同时重置分页到第 1 页 |

### 8.2 视图切换

- 列表页提供「列表视图」与「卡片视图」切换按钮。
- 系统根据品牌总数智能默认视图：≤20 默认卡片视图，>20 默认列表视图。
- 用户手动切换后，当前会话内保持用户选择。

### 8.3 级联选择

在业务单据中引用品牌库时，采用三级级联：

```
品牌 → 产品线 → 型号
```

- 选择品牌后，产品线下拉仅显示该品牌下的启用产品线。
- 选择产品线后，型号下拉仅显示该产品线下的启用型号。
- 支持直接搜索型号，反填品牌和产品线。
- 已禁用品牌/型号在级联中置灰，不可选。

### 8.4 操作反馈

| 操作 | 反馈方式 |
|---|---|
| 新建成功 | Toast 提示「品牌创建成功，等待审批」或「品牌已启用」 |
| 审批通过 | Toast 提示「已通过，品牌/型号已生效」 |
| 审批驳回 | 弹窗展示驳回原因，单据状态变为「被驳回」 |
| 启用/禁用 | 二次确认弹窗，操作成功后列表状态标签实时更新 |
| 批量导入 | 上传后展示校验结果：成功 N 条、失败 M 条，失败可下载错误报告 |
| 注册证到期 | 系统消息 + 列表页「即将到期」标签高亮 |

### 8.5 空态设计

| 空态场景 | 展示内容 |
|---|---|
| 品牌库为空 | 插图 + 「暂无品牌数据，点击新建第一个品牌」 |
| 搜索无结果 | 「未找到匹配的品牌/型号，请更换关键词或申请新增」 |
| 型号列表为空 | 「该品牌下暂无型号，点击新增型号」 |
| 注册证为空 | 「暂无注册证，请及时上传以规避合规风险」 |
| 引用统计为空 | 「暂无业务引用记录」 |

### 8.6 关键字段校验

- 品牌编码、型号编码、厂家编码全系统唯一。
- 同一品牌下产品线名称唯一。
- 型号名称 + 规格组合在同一品牌下唯一。
- 注册证号格式校验（境内/境外规则不同）。
- 有效期至必须大于批准日期。

### 8.7 批量导入交互

1. 点击「批量导入」→ 下载 Excel 模板。
2. 填写品牌/型号/注册证信息。
3. 上传文件，系统预校验：必填项、唯一性、格式、注册证有效性。
4. 展示校验结果，失败行可在线编辑或下载错误报告。
5. 确认导入后写入系统，触发新建/变更审批（视配置而定）。

### 8.8 异常处理规则

| 异常场景 | 触发条件 | 前端表现 | 后端处理 | 用户引导 |
|---|---|---|---|---|
| **网络错误** | 保存/查询时网络断开或超时（>10s 无响应） | Toast 提示「网络异常，请检查网络后重试」 | 请求失败不入库，接口返回 500/503/timeout | 提供「重试」按钮；列表页支持离线缓存最近一页 |
| **表单校验错误** | 必填项为空、编码重复、格式不符、唯一性冲突 | 字段级红色提示 + 页面滚动至首个错误项 | 校验不通过时不落库，返回具体错误字段与原因 | 提示用户按规则修改；重复编码给出「查看已有数据 / 强制新建 / 合并」选项 |
| **并发修改冲突** | 多人同时编辑同一品牌/型号，后提交者版本号落后 | 弹窗提示「数据已被他人更新，请刷新后重试」 | 基于乐观锁（version 字段）拒绝覆盖，返回最新数据 | 提供「刷新查看最新内容 / 覆盖（需二次确认）」 |
| **注册证过期/缺失** | 引用时注册证已过期或未上传 | 选择器中该型号置灰，Hover 提示「注册证已过期，不可引用」 | 接口过滤掉不可引用状态，记录预警日志 | 引导用户联系产品运营补充注册证 |
| **无权限访问** | 用户尝试访问无数据范围的品牌/型号 | 页面展示 403 空态「暂无权限查看该数据」 | API 层统一鉴权，返回 403 | 提示联系管理员申请权限 |
| **批量导入失败** | 模板格式错误、必填缺失、数据重复 | 弹窗展示成功/失败条数，失败可下载错误报告 | 整批事务回滚或部分成功（按配置），返回错误明细 | 引导下载错误报告修正后重新上传 |
| **审批流异常** | 审批人缺失、审批节点配置错误 | 提交后提示「当前审批流不可用，请联系管理员」 | 记录异常日志，转交系统管理员 | 提供「联系管理员」快捷入口 |

### 8.9 快捷操作规则

| 快捷操作 | 触发方式 | 适用页面 | 执行效果 | 权限要求 |
|---|---|---|---|---|
| **全局搜索** | 列表页顶部搜索框输入关键词，回车或失焦后触发 | 品牌库列表页、品牌选择器 | 按品牌名/型号名/厂家名/注册证号模糊搜索；支持防抖 300ms | 按数据可见范围过滤结果 |
| **新建品牌** | 列表页右上角「+ 新建品牌」按钮 | 品牌库列表页 | 打开新建品牌抽屉 | 产品运营、系统管理员、销售经理（申请） |
| **快速编辑** | 列表行内「编辑」按钮或详情页「编辑」 | 列表页、详情页 | 打开编辑抽屉并定位到对应字段 | 有编辑权限的角色 |
| **启用/禁用切换** | 列表操作栏或详情页状态开关 | 列表页、详情页 | 二次确认后切换状态，列表标签实时刷新 | 产品运营、系统管理员 |
| **批量导入** | 列表页「批量导入」按钮 | 品牌库列表页 | 打开批量导入弹窗，下载模板并上传 | 产品运营、系统管理员 |
| **导出数据** | 列表页「导出」按钮 | 品牌库列表页 | 按当前筛选条件导出 Excel/CSV | 产品运营、销售经理、商务运营、合规专员 |
| **纠错反馈** | 业务单据/选择器中「数据有误？」入口 | 品牌选择器、业务单据 | 打开纠错反馈抽屉，提交错误类型与说明 | 销售代表及以上查看权限 |
| **最近使用** | 品牌选择器默认展示最近引用的 5-10 条 | 品牌选择器弹窗 | 点击后直接回填品牌/产品线/型号 | 按数据可见范围过滤 |
| **键盘快捷键** | `Ctrl/Cmd + K` 聚焦搜索框；`Esc` 关闭抽屉/弹窗 | 列表页、详情页、弹窗 | 提升高频操作效率 | 无特殊权限要求 |

## 九、权限与数据范围设计

### 9.1 角色权限矩阵

| 角色 | 查看 | 新建 | 编辑 | 启用/禁用 | 删除 | 导入/导出 | 审批 |
|---|---|---|---|---|---|---|---|
| 系统管理员 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |
| 产品运营 | 是 | 是 | 是 | 是 | 否 | 是 | 是 |
| 销售经理 | 是 | 是（申请） | 是（申请） | 否 | 否 | 是 | 是 |
| 销售代表 | 是 | 是（纠错反馈） | 否 | 否 | 否 | 否 | 否 |
| 商务运营 | 是 | 否 | 否 | 否 | 否 | 是 | 否 |
| 渠道管理员 | 是 | 否 | 否 | 否 | 否 | 否 | 否 |
| 合规专员 | 是 | 否 | 否 | 否 | 否 | 是 | 否 |

> **说明**：
> - 「是（申请）」表示可提交新建/编辑申请，需审批后生效。
> - 「是（纠错反馈）」表示销售代表无直接新建品牌/型号权限，仅可通过纠错反馈提交数据问题，由产品运营核实处理。
> - 删除权限仅对「无任何业务引用」的品牌/型号开放；已有引用时仅可禁用，不可物理删除。

### 9.2 数据可见性与脱敏规则

| 角色 | 可见范围 | 脱敏规则 |
|---|---|---|
| 系统管理员 | 全部品牌/厂家/型号 | 无脱敏 |
| 产品运营 | 全部品牌/厂家/型号 | 无脱敏 |
| 销售经理 | 全部品牌/厂家/型号（可配置为仅本区域代理品牌） | 注册证附件默认只读，不可下载 |
| 销售代表 | 已启用品牌/型号，且受限于渠道授权范围 | 注册证附件、厂家联系方式隐藏；仅可见品牌/型号基础信息 |
| 商务运营 | 全部已启用品牌/厂家/型号 | 注册证附件可查看但不可下载；**价格字段不在品牌库维护，无脱敏问题** |
| 渠道管理员 | 本公司代理或授权的品牌范围 | 仅可见授权品牌/型号基础信息 |
| 合规专员 | 全部品牌及注册证信息 | 无脱敏，可下载注册证附件 |

> **关于价格字段的说明**：品牌库为产品主数据底座，**不维护任何价格字段**（如出厂价、经销价、终端价）。价格数据由业务模块（意向管理、设备管理、试剂运营等）自行维护，并按各自模块的权限规则脱敏。品牌库返回的数据中不含价格信息，因此不存在价格字段脱敏问题。

### 9.3 数据范围控制

- **品牌授权范围**：渠道管理员可为经销商配置可代理品牌，控制其在前端选择器中可见品牌。
- **产品线可见性**：支持按角色隐藏某些产品线（如内部产品不对经销商开放）。
- **型号状态控制**：已禁用型号在业务单据中不可选，但历史单据可正常查看。
- **注册证敏感信息**：注册证附件仅对指定角色开放下载，其他角色仅可查看证号与有效期。

## 十、核心设计原则与要点

| 原则 | 说明 |
|---|---|
| **主数据唯一性** | 每个品牌、型号、厂家、注册证均有全局唯一编码与主键，禁止一物多码。 |
| **跨应用复用** | 品牌库是线索、意向、设备、试剂、售后、客户 360 等模块的唯一产品数据来源。 |
| **引用而非复制** | 业务单据保存主键 + 快照，避免数据冗余，同时保证历史可追溯。 |
| **生命周期可控** | 品牌/型号支持启用、禁用、审批、驳回等状态，关键变更走审批流。 |
| **数据标准化** | 统一品牌命名、编码规则、产品线划分、规格单位，确保统计口径一致。 |
| **合规前置** | 注册证、有效期、生产企业等监管字段集中管理，支持到期预警。 |
| **操作可追溯** | 所有主数据变更写入日志，记录变更前/后值，支撑审计。 |
| **开放可扩展** | 产品运营可自助维护，降低对研发的依赖；预留与 ERP/MDM 对接能力。 |

## 十一、与其它模块的关联

| 关联模块 | 关联方式 | 数据流向 |
|---|---|---|
| **线索管理** | 线索录入时选择产品线/型号 | 品牌库 → 线索：带出品牌、产品线、型号 |
| **意向管理** | 意向报备时选择品牌/型号 | 品牌库 → 意向：带出生产企业、注册证、规格 |
| **客户 360度** | 设备地图、试剂账本按品牌/型号聚合 | 品牌库 → 客户 360度：展示客户侧产品覆盖 |
| **设备管理** | 创建设备档案时选择型号 | 品牌库 → 设备：确定设备品牌、型号、保修策略 |
| **试剂运营** | 试剂消耗记录关联型号 | 品牌库 → 试剂：按品牌/型号统计消耗、复购预警 |
| **售后工单** | 报修时选择设备型号 | 品牌库 → 售后：定位设备品牌、型号、保修状态 |
| **目标绩效** | 按品牌/产品线统计销售额、装机量 | 业务单据 → 经营驾驶舱：按品牌库维度汇总 |
| **经营驾驶舱** | 品牌销售排行、市场份额分析 | 业务单据 → 驾驶舱：基于品牌库主键聚合 |
| **渠道管理** | 配置经销商代理品牌范围 | 品牌库 → 渠道：控制渠道可见可选品牌 |

> **关键提示**：品牌库是**跨业务通用主数据入口**，任何涉及产品/品牌/型号的选择器均应调用品牌库服务，禁止各业务模块自行维护产品字典。

## 十二、未考虑到的问题补充（开发者视角）

以下问题在需求文档中容易被忽略，开发阶段需重点关注：

1. **编码规则可配置**：品牌、型号、厂家编码规则需支持管理员后台配置，避免硬编码。
2. **历史数据迁移**：旧系统中已有的产品数据如何清洗、去重、映射到新的品牌库主键，需制定迁移方案。
3. **重复数据合并**：当发现重复品牌/型号时，需提供合并工具，并保留历史引用关系（使用主键映射表）。
4. **级联选择性能**：品牌/型号数据量大时，级联选择器需支持懒加载、分页加载、关键字搜索，避免一次性加载全部数据。
5. **多语言/多币种**：如未来拓展海外市场，品牌名称、规格是否支持多语言，注册证是否按国家区分。
6. **图片与附件存储**：品牌 LOGO、产品图片、注册证附件需统一接入文件服务，支持缩略图、水印、权限控制、CDN 加速。
7. **全文检索能力**：品牌、型号、厂家、注册证号需支持全文检索，建议接入 Elasticsearch 或数据库全文索引。
8. **数据权限下沉**：品牌库的数据权限需在 API 层统一控制，避免前端隐藏后接口仍可访问。
9. **变更影响分析**：修改关键字段前，需实时计算影响范围（引用单据数、模块分布），并提供「仅改主数据 / 同步刷新快照」选项。
10. **注册证到期任务**：需设计定时任务扫描注册证有效期，提前 90/60/30 天推送消息，并在列表页高亮。
11. **批量导入幂等性**：重复导入同一份 Excel 时，需根据编码或唯一键做幂等处理，避免重复创建。
12. **与其他系统对接**：预留与 ERP、WMS、MDM 等外部系统的产品主数据同步接口，支持单向/双向同步。
13. **软删除与归档**：禁止物理删除已有引用的主数据，删除操作实际为「禁用」或「标记删除」，保留历史记录。
14. **审计日志字段级**：操作日志需记录字段级变更前/后值，而不仅仅是「某用户编辑了型号」。
15. **移动端适配**：品牌库选择器在小程序端需适配小屏幕，支持搜索优先、最近使用、级联简化。
16. **数据质量评分**：可对品牌/型号的完整度进行评分（如是否上传 LOGO、注册证、规格），帮助产品运营持续治理。
17. **API 版本控制**：品牌库作为被多个模块依赖的核心服务，对外 API 需做好版本控制，避免breaking change影响下游。
18. **禁用后的兜底显示**：已禁用品牌/型号在历史单据中仍需正常显示名称，前端需处理好「已禁用」标签与置灰样式。
