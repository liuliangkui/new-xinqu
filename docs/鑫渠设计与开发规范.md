## 引言

本文档是鑫渠 CRM 产品设计与前端开发的指导性文件。所有新增页面、功能迭代、视觉调整都应遵循本文档定义的原则与规范，确保产品在用户体验上保持一致性、可预测性和高效性。

## 一、页面布局设计规范

### 1.1 设计目标

页面布局的目标是让用户在最短时间内完成「认知 → 定位 → 行动」的闭环：

1. **认知**：用户进入页面后，第一眼就能了解当前业务状态。
2. **定位**：通过导航、筛选快速找到目标数据。
3. **行动**：在目标数据上执行最合理的下一步操作。

### 1.2 统一信息分层

所有列表型页面必须遵循以下五层结构，从上到下依次排列：

```
┌─────────────────────────────────────────────┐
│ 第一层：全局指标 / 统计卡片                  │
├─────────────────────────────────────────────┤
│ 第二层：导航 / 分类 Tab / 视图切换 / 主操作  │
├─────────────────────────────────────────────┤
│ 第三层：搜索 / 筛选                         │
├─────────────────────────────────────────────┤
│ 第四层：明细内容（卡片网格 / 表格）          │
├─────────────────────────────────────────────┤
│ 第五层：分页 / 加载更多                     │
└─────────────────────────────────────────────┘
```

### 1.3 各层设计规则

| 层级 | 内容 | 设计规则 |
|---|---|---|
| 第一层 | 统计卡片 | 数量 3-5 个，使用 KPI 样式，关键指标用颜色区分 |
| 第二层 | Tab + 视图切换 + 主按钮 | 左侧导航，右侧操作；主按钮用 `btn-primary`，次按钮用 `btn-ghost` |
| 第三层 | 搜索 + 筛选 | 搜索框最左，筛选条件横向排列，不超过 5 个 |
| 第四层 | 卡片/表格 | 默认卡片视图（数据 ≤20），默认列表视图（数据 >20） |
| 第五层 | 分页 | 底部分页，显示页码信息和翻页按钮 |

### 1.4 双态结构规范

具有「数据列表 + 详情查看」的模块，统一采用双态结构：

- **列表态**：用于扫描、筛选、定位，占据整个内容区。
- **详情态**：用于深度查看和操作，可通过以下方式呈现：
  - 新页面覆盖（客户 360°）
  - 右侧抽屉（线索详情、联系人详情）
  - 弹窗（意向审批、冲突裁决）

**切换规则**：
- 从列表进入详情：点击卡片/行
- 从详情返回列表：顶部「返回」按钮或点击遮罩关闭抽屉/弹窗

### 1.5 间距规范

| 元素 | 间距规则 |
|---|---|
| 页面内边距 | `p-4` 或 `p-5`（16px / 20px） |
| 模块间距 | `gap-4`（16px） |
| 卡片内部间距 | `p-4`（16px） |
| 表单项间距 | `gap-4` 或 `space-y-4` |
| 按钮间距 | `gap-2`（8px） |

### 1.6 页面标题规范

- 页面标题使用 `section-title` 类（17px，font-weight 600）
- 标题右侧放置主操作按钮
- 详情页标题下方放置对象关键标签（等级、区域、状态等）

### 1.7 禁止事项

- 禁止将筛选条件放在统计卡片上方
- 禁止同一页面出现多个主操作按钮并列
- 禁止详情页没有明确的返回入口
- 禁止列表页无空态提示

### 1.8 数据分析类页面的 AI 结论区域

**适用页面**：经营驾驶舱、效益中心、数据洞察中心、目标绩效、试剂运营、返利与佣金、资质管理、意向管理、渠道秩序等以统计、趋势、对比、漏斗分析为主要内容的页面。

**布局原则**：

```
┌─────────────────────────────────────────────┐
│ 上层：统计卡片 / KPI / 图表 / 表格 / 明细     │
├─────────────────────────────────────────────┤
│ 下层：AI 分析结论区域（必须置于页面底部）     │
└─────────────────────────────────────────────┘
```

- **数据在上，结论在下**：所有 AI 生成的分析结论、归因、风险预警、经营建议、行动建议，必须放在页面主体数据的**最下方**，作为“看完数据后的总结”。
- **阅后决策模式**：用户应先看完整页指标和明细，再查看 AI 给出的解读，并据此判断是否认同、是否需要采取行动。
- **不可前置**：禁止将 AI 分析结论放在统计卡片之前、图表上方或筛选区附近，避免结论先于数据干扰用户独立判断。

**内容结构**：

AI 结论区域统一使用带 `icon-ai` 图标的卡片，标题为 **“AI 分析结论”**，内部包含两类内容：

1. **关键洞察卡片（3 列栅格）**：用颜色区分风险/机会/健康状态，每个卡片一句话结论 + 一句话数据支撑。
2. **行动建议区**：一段或多条可执行建议，明确“下一步该做什么”。

**示例结构**：

```html
<!-- AI 分析结论 -->
<div class="card p-4 mb-5">
  <div class="flex items-center gap-2 mb-4">
    <svg class="icon icon-md text-primary"><use href="#icon-ai"/></svg>
    <h3 class="font-semibold text-ink">AI 分析结论</h3>
  </div>
  <div class="grid grid-cols-1 md:grid-cols-3 gap-4 mb-4">
    <div class="p-4 rounded-lg bg-success-bg">...</div>
    <div class="p-4 rounded-lg bg-warning-bg">...</div>
    <div class="p-4 rounded-lg bg-danger-bg">...</div>
  </div>
  <div class="p-3 rounded-lg bg-panel">
    <div class="text-sm font-medium text-ink mb-2">经营建议</div>
    <div class="text-sm text-sub">1. ... 2. ... 3. ...</div>
  </div>
</div>
```

## 二、卡片设计规范

### 2.1 设计目标

卡片是鑫渠 CRM 最核心的信息载体之一。卡片设计的核心是：**在不进入详情的前提下，帮助用户完成决策**。

### 2.2 卡片 = 对象 + 状态 + 下一步动作

每张卡片必须包含三类信息：

1. **对象标识**：让客户/项目/线索被唯一识别
2. **状态信息**：让用户知道当前处于什么阶段
3. **下一步动作**：提供当前状态下最合理的操作

### 2.3 卡片结构

```
┌─────────────────────────────────────┐
│ [状态标签]              [操作按钮]  │  ← 顶部：状态 + 操作
├─────────────────────────────────────┤
│ 对象名称（加粗，最大字号）          │  ← 主体：对象标识
│ 辅助信息（客户、科室、来源等）      │
├─────────────────────────────────────┤
│ 关键指标（金额、倒计时、健康度）    │  ← 底部：决策依据
└─────────────────────────────────────┘
```

### 2.4 卡片视觉规范

| 元素 | 规范 |
|---|---|
| 背景 | 白色 `card` 类，圆角 12px，阴影 `var(--shadow-card)` |
| 悬停效果 | `card-hover` 类，轻微上浮 + 阴影加深 |
| 状态标签 | 使用 `badge` 类，颜色按状态语义 |
| 对象名称 | 14-15px，font-weight 600，单行截断 |
| 辅助信息 | 13px，`text-sub` 颜色 |
| 操作按钮 | 文本链接或小型按钮，不超过 2 个 |

### 2.5 不同模块卡片差异化规范

#### 2.5.1 客户 360° 卡片

**定位**：客户档案封面，引导进入详情。

**必显字段**：
- 医院名称
- 等级 + 区域
- 健康度评分
- 科室数 / 装机数 / 在跟意向
- 负责人
- 最近动态

**操作按钮**：
- 主操作：「查看」（进入详情）
- 可选：「预约拜访」「新建意向」

**为什么这样设计**：客户卡片不承担复杂处理，核心是让人判断「这个客户要不要深入看」。

#### 2.5.2 线索管理卡片

**定位**：分拣台，决定线索该给谁跟进或是否废弃。

**必显字段**：
- 客户名称
- 科室
- 线索摘要
- 来源
- 状态
- 跟进倒计时

**操作按钮（按状态）**：

| 状态 | 操作 | 说明 |
|---|---|---|
| 待分配 | 分配 / 领取 | 确定归属人 |
| 跟进中 | 跟进 | 更新进度 |
| 已转意向 | 查看 | 原线索冻结 |
| 已废弃 | 查看 / 恢复 | 无价值或恢复处理 |

**为什么这样设计**：线索的核心问题是「分给谁」，操作按钮直接对应归属处理。

#### 2.5.3 意向管理卡片

**定位**：流程节点看板，每个状态对应一个处理动作。

**必显字段**：
- 项目名称
- 客户名称
- 业务类型
- 预计金额
- 当前阶段
- 保护期剩余
- 负责人
- 状态

**操作按钮（按状态）**：

| 状态 | 操作 | 说明 |
|---|---|---|
| 草稿 | 编辑 / 提交 | 完善并提交 |
| 审批中 | 审批 | 审批人审核 |
| 冲突 | 裁决 | 冲突裁决人判定 |
| 生效中 | 跟进 | 持续跟进 |
| 被驳回 | 重新提交 | 修改后再次提交 |

**为什么这样设计**：意向的核心问题是「流程走到哪、该谁处理」，操作按钮直接对应流程推进。

### 2.6 卡片布局规范

- 卡片视图默认 4 列网格（`grid-cols-4 gap-4`）
- 每页显示 8 张卡片
- 卡片高度不固定，但应保持一致（使用 `flex flex-col`）
- 卡片内操作按钮右对齐或底部对齐

### 2.7 禁止事项

- 禁止一张卡片上放超过 3 个操作按钮
- 禁止卡片信息超过 7 个字段
- 禁止使用相同颜色的状态标签表示不同含义
- 禁止卡片无悬停反馈

## 三、列表/表格设计规范

### 3.1 设计目标

列表视图用于**高密度信息展示和批量处理**。当数据量较大或需要对比多字段时，优先使用列表视图。

### 3.2 列表 vs 卡片的选择规则

| 场景 | 推荐视图 | 原因 |
|---|---|---|
| 数据量 ≤20 | 卡片视图 | 视觉友好，便于概览 |
| 数据量 >20 | 列表视图 | 信息密度高，便于扫描 |
| 需要批量操作 | 列表视图 | 支持多选复选框 |
| 需要对比多字段 | 列表视图 | 表头对齐，便于横向对比 |
| 管理层概览 | 卡片视图 | 重点信息突出 |

### 3.3 表格结构规范

```
┌─────────────────────────────────────────────────────────────┐
│ 字段A   │ 字段B   │ 字段C   │ 字段D   │ 字段E   │ 操作     │
├─────────┼─────────┼─────────┼─────────┼─────────┼──────────┤
│ 数据    │ 数据    │ 数据    │ 数据    │ 数据    │ [查看]   │
│ 数据    │ 数据    │ 数据    │ 数据    │ 数据    │ [审批]   │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 表头规范

- 表头使用 `table th` 样式：背景 `#FAFBFC`，字号 12px，颜色 `var(--sub)`
- 表头文字左对齐，操作列居中
- 支持表头排序的字段，点击后显示 ↑ / ↓ 箭头

### 3.5 表格行规范

- 行高适中，保证可读性
- 行悬停背景色 `#FAFCFF`
- 操作列固定在最右侧
- 状态标签使用 `badge` 类
- 长文本使用 `text-marquee-trigger` + `text-marquee` 实现悬停滚动

### 3.6 分页规范

- 列表视图每页 12 条
- 卡片视图每页 8 条
- 分页组件显示：
  - 左侧：「1 / 5 页，共 56 条」
  - 右侧：「上一页」 [1] [2] [3] ... [5] 「下一页」
- 切换视图、筛选、Tab 后自动重置到第 1 页

### 3.7 空态规范

列表无数据时必须显示空态：

```
┌─────────────────────────────────────┐
│           [空态图标]                │
│         暂无相关数据                │
│   点击下方按钮创建第一条记录        │
│        [+ 新建 XXX]                 │
└─────────────────────────────────────┘
```

### 3.8 禁止事项

- 禁止表格列数超过 10 列
- 禁止表格行无悬停效果
- 禁止分页信息显示不完整
- 禁止无数据时不显示空态

## 四、统计指标（KPI）设计规范

### 4.1 设计目标

统计指标帮助用户**快速把握业务全局**，识别需要优先处理的事项。

### 4.2 KPI 卡片结构

```
┌─────────────────────┐
│ 指标标签（小字）     │
│ 指标数值（大字）     │
└─────────────────────┘
```

### 4.3 视觉规范

| 元素 | 规范 |
|---|---|
| 容器 | `card p-4`，圆角 12px |
| 标签 | `text-xs text-sub`，最多 8 个汉字 |
| 数值 | `text-2xl font-bold` 或 `kpi-value`（26px） |
| 颜色 | 默认黑色；正向指标绿色；风险指标红色；进行中指标蓝色/橙色 |

### 4.4 颜色语义

| 颜色 | 使用场景 | 示例 |
|---|---|---|
| 黑色/灰色 | 中性指标、总量指标 | 客户总数、本月意向数 |
| 蓝色 | 进行中、生效中 | 生效中、跟进中 |
| 橙色 | 待处理、关注 | 待审批、待分配 |
| 红色 | 风险、冲突、高危 | 冲突待裁决、风险客户 |
| 绿色 | 健康、完成、正向 | 健康客户、本月成交率 |

### 4.5 数量规范

- 列表页顶部 KPI 卡片数量：3-5 个
- 避免超过 5 个导致视觉拥挤
- KPI 应与当前页面核心业务直接相关

### 4.6 各模块 KPI 示例

| 模块 | KPI 指标 |
|---|---|
| 客户 360° | 客户总数、健康客户、风险客户、今日待拜访 |
| 线索管理 | 本月新增、待分配、跟进中、转意向率 |
| 意向管理 | 本月意向数、生效中、待审批、冲突待裁决、本月成交率 |
| 日历 | 今日日程数、本周日程数、待完成任务 |

### 4.7 禁止事项

- 禁止使用 KPI 展示与当前页面无关的指标
- 禁止同一页面使用多个红色 KPI 造成恐慌
- 禁止 KPI 数值无单位或含义不明

## 五、导航设计规范

### 5.1 设计目标

导航帮助用户**明确当前位置、快速切换模块、找到目标功能**。

### 5.2 全局导航：侧边栏

```
┌─────────────────┐
│ 鑫渠 Logo       │
├─────────────────┤
│ 💬 消息          │
│ 📅 日历          │
│ 📋 工作台        │
│ 📇 通讯录        │
│ ✅ 任务          │
│ 🧩 应用中心      │  ← 业务应用入口
│ ⭐ 收藏          │
├─────────────────┤
│ 用户信息         │
└─────────────────┘
```

### 5.3 侧边栏规范

- 一级导航：消息、日历、工作台、通讯录、任务、应用中心、收藏
- 业务应用统一放在「应用中心」，不在侧边栏平铺
- 当前页面高亮：`nav-item.active` 类
- 图标 + 文字，图标起识别作用

### 5.4 应用中心规范

- 应用按业务域分组展示，分组顺序：业务管理 → 渠道协同 → 合规审计 → 数据决策
- 应用顺序：
  - 业务管理：线索管理、意向管理、意向审批中心、客户 360°、设备管理、试剂运营、售后工单、工单看板、品牌库管理
  - 渠道协同：经销商协同
  - 合规审计：合规风控
  - 数据决策：目标绩效、经营驾驶舱
- 新增应用必须对应到第八章的某一种布局模板，并在原型中提供案例页面
- 每个应用显示图标、名称、描述；描述说明应用核心用途，不超过 10 个汉字
- 支持按角色权限显示/隐藏应用
- 已添加到工作台的应用显示「已添加」状态，无权限应用置灰并禁用点击

**应用中心分组示例**：

```
┌─ 业务管理 ─┐
│ 📥 线索管理  🛡️ 意向管理  ✍️ 意向审批中心  🏥 客户 360°  🔬 设备管理  🧪 试剂运营  🔧 售后工单  📋 工单看板  🏷️ 品牌库管理 │
├─ 渠道协同 ─┤
│ 🤝 经销商协同                                                                          │
├─ 合规审计 ─┤
│ ✅ 合规风控                                                                            │
├─ 数据决策 ─┤
│ 🎯 目标绩效    📊 经营驾驶舱                                                            │
└───────────┘
```

### 5.5 页面内导航：Tab 标签

- 用于同一页面内不同状态/维度的切换
- Tab 顺序应符合业务逻辑
- 当前 Tab 高亮显示
- 切换 Tab 后保留其他筛选条件，但重置分页

### 5.6 页面内导航：页签（Tabs）

- 用于详情页内不同维度的内容切换
- 页签名称简洁明确（2-4 个汉字）
- 当前页签下划线高亮
- 页签内容切换时可有淡入动画

### 5.7 面包屑导航

- 用于层级较深的页面（如客户 360° 详情页 → 科室 360° 子页面）
- 格式：`客户 360° / 昆明市第一人民医院 / 检验科`
- 点击上级面包屑可返回

### 5.8 禁止事项

- 禁止侧边栏超过 10 个一级入口
- 禁止 Tab 数量超过 7 个
- 禁止页签名称过长或含义模糊
- 禁止导航层级超过 4 层

## 六、搜索与筛选设计规范

### 6.1 设计目标

搜索和筛选帮助用户**从大量数据中快速定位目标记录**。

### 6.2 搜索框规范

- 位置：筛选栏最左侧
- 占位文案：说明可搜索的字段，如「搜索客户、项目、负责人...」
- 图标：左侧 🔍 搜索图标
- 触发方式：输入时实时搜索（debounce 300ms）
- 清空：输入后有清空按钮（可选）

### 6.3 筛选条件规范

- 数量：一般不超过 5 个筛选条件
- 排列：横向排列，超出时折叠为「更多筛选」
- 类型：下拉选择器、日期选择器、单选按钮组
- 触发方式：下拉选择后即时触发筛选

### 6.4 筛选条件设计原则

| 模块 | 核心筛选维度 | 原因 |
|---|---|---|
| 客户 360° | 区域、等级、健康度、负责人 | 按客户属性分层 |
| 线索管理 | 来源、状态、时间范围 | 按线索质量和处理状态分流 |
| 意向管理 | 业务类型、时间范围 | 按业务模式和周期筛选 |

### 6.5 快捷筛选 Tab

- 用于最常用的筛选组合
- 位置：统计卡片下方、详细筛选上方
- 示例：「我的客户」「风险客户」「待拜访」「全部」
- 与详细筛选条件联动，切换 Tab 时更新筛选条件

### 6.6 筛选结果反馈

- 筛选后实时更新列表
- 显示当前筛选结果数量
- 提供「清空筛选」按钮

### 6.7 搜索 + 筛选的联动规则

- 搜索和筛选条件可同时生效
- 切换视图（卡片/列表）时保留搜索和筛选条件
- 切换 Tab 时，搜索条件保留，部分筛选条件可能重置

### 6.8 禁止事项

- 禁止筛选条件过多导致一行放不下
- 禁止筛选后无结果反馈
- 禁止搜索框占位文案过于笼统（如只写「搜索」）
- 禁止筛选条件之间逻辑冲突（如同时选「全部区域」和具体区域）

## 七、应用布局模板库

> 不同业务属性的应用应选用不同的布局模板。新增应用时，先匹配模板类型，再设计具体页面，避免所有页面套同一个结构。

### 7.1 模板选择决策树

```
是否需要按状态流转？        是 → 看板/流程模板（D）
    ↓ 否
是否以单个对象为中心聚合信息？ 是 → 详情全景模板（B）
    ↓ 否
是否以时间为核心组织内容？    是 → 日历时间轴模板（E）
    ↓ 否
是否需要监控指标与趋势？      是 → 数据驾驶舱模板（F）
    ↓ 否
是否以信息流/沟通为主？       是 → 信息流模板（H）
    ↓ 否
是否用于结构化配置录入？      是 → 表单配置模板（G）
    ↓ 否
默认使用列表-筛选-处理模板（A）
```

### 7.2 模板 A：列表-筛选-处理模板（List-Filter-Action）

**适用应用**：线索管理、意向管理、客户 360° 列表、产品库

**信息架构**：

```
┌─────────────────────────────────────────────┐
│ 页面标题                          [主操作]   │
├─────────────────────────────────────────────┤
│ KPI 统计卡片（3-5 个）                       │
├─────────────────────────────────────────────┤
│ Tab / 视图切换 / 批量操作                    │
├─────────────────────────────────────────────┤
│ 搜索 + 筛选条件                              │
├─────────────────────────────────────────────┤
│ 卡片网格 / 数据表格                          │
├─────────────────────────────────────────────┤
│ 分页 / 加载更多                              │
└─────────────────────────────────────────────┘
```

**核心组件**：统计卡片、Tab、视图切换按钮、搜索框、筛选器、卡片/表格、分页
**交互要点**：状态驱动操作、默认卡片视图（≤20 条）、默认列表视图（>20 条）、筛选后重置分页

### 7.3 模板 B：详情全景模板（Detail-Insight）

**适用应用**：客户 360° 详情、科室 360°、经销商档案

**信息架构**：

```
┌─────────────────────────────────────┐
│ 返回 │ 对象标题 │ 关键标签 │ 主操作  │
├─────────────────────────────────────┤
│ 左侧信息区      │ 右侧页签内容区      │
│ · 基础档案      │ · 概览              │
│ · 关键指标      │ · 子对象列表        │
│ · 负责人/团队   │ · 时间线            │
│ · 最近动态      │ · 关系图谱          │
└─────────────────────────────────────┘
```

**核心组件**：对象封面、标签组、页签、时间线、指标卡片、关系图谱
**交互要点**：顶部是对象封面，左侧静态档案，右侧用页签切换不同维度

### 7.4 模板 C：流程审批模板（Approval-Flow）

**适用应用**：意向报备审批、冲突裁决、合同审批

**信息架构**：

```
┌─────────────────────────────────────┐
│ 申请单摘要 │ 当前节点 │ 操作按钮    │
├─────────────────────────────────────┤
│ 左侧：审批记录/时间线               │
│ 右侧：申请表单详情                  │
│ 底部：审批意见 + 通过/驳回/转交     │
└─────────────────────────────────────┘
```

**核心组件**：流程图/时间线、申请表单、意见输入、审批操作按钮
**交互要点**：当前节点高亮，审批必须留痕，驳回需说明原因

### 7.5 模板 D：看板/流程跟踪模板（Kanban-Board）

**适用应用**：售后工单、任务看板、项目里程碑

**信息架构**：

```
┌─────────┬─────────┬─────────┬─────────┐
│ 待处理  │ 处理中  │ 待验收  │ 已完成  │
│ [卡片]  │ [卡片]  │ [卡片]  │ [卡片]  │
└─────────┴─────────┴─────────┴─────────┘
```

**核心组件**：状态列、卡片、拖拽句柄、列顶计数
**交互要点**：状态列横向排布，卡片可拖拽流转，列顶显示数量

### 7.6 模板 E：日历时间轴模板（Calendar-Timeline）

**适用应用**：日历、拜访计划、会议安排

**信息架构**：

```
┌─────────────────────────────────────┐
│ 视图切换：日 / 周 / 月              │
├─────────────────────┬───────────────┤
│   日历主体          │ 日期选择器     │
│   （小月历）        │ 今日/选中日程  │
│                     │ · 日程条目     │
│                     │ · 颜色图例     │
└─────────────────────┴───────────────┘
```

**核心组件**：小月历、日期选择器、日程列表、颜色图例、新建按钮
**交互要点**：右侧日程随日期切换，颜色标签分类，支持冲突提示

### 7.7 模板 F：数据驾驶舱模板（Dashboard）

**适用应用**：经营驾驶舱、目标绩效、销售漏斗

**信息架构**：

```
┌─────────────────────────────────────┐
│ 核心 KPI 大图（1-4 个）              │
├─────────────┬───────────────────────┤
│ 趋势图表    │ 排行榜/漏斗图          │
├─────────────┴───────────────────────┤
│ 明细下钻表格 / 预警列表              │
└─────────────────────────────────────┘
```

**核心组件**：KPI 大图、趋势图、饼图/漏斗图、排行榜、预警卡片
**交互要点**：大图强调关键指标，图表支持时间维度切换，支持下钻

### 7.8 模板 G：表单配置模板（Form-Config）

**适用应用**：产品库、品牌库、用户权限、审批流配置

**信息架构**：

```
┌─────────────────────────────────────┐
│ 配置名称 │ 保存 / 取消              │
├─────────────────────────────────────┤
│ 左侧：配置项分类导航                 │
│ 右侧：表单字段区                     │
│       · 基础信息                     │
│       · 规则设置                     │
│       · 关联关系                     │
└─────────────────────────────────────┘
```

**核心组件**：分组导航、表单字段、规则编辑器、关联选择器
**交互要点**：复杂配置分步骤/分组，实时校验，变更提示未保存

### 7.9 模板 H：信息流/协同模板（Feed-Collaboration）

**适用应用**：消息中心、任务评论、通知中心

**信息架构**：

```
┌─────────────────────────────────────┐
│ 筛选：全部 / 未读 / @我             │
├─────────────────────────────────────┤
│ [头像] 标题              时间       │
│ 内容摘要                            │
│ [头像] 标题              时间       │
│ 内容摘要                            │
└─────────────────────────────────────┘
```

**核心组件**：消息项、头像、未读标记、时间戳、筛选标签
**交互要点**：按时间倒序，未读高亮，点击跳转到业务上下文

### 7.10 模板组合使用

一个应用可以主模板 + 局部模板组合：

- 客户 360° 列表用模板 A，进入详情用模板 B，详情里的「意向列表」又嵌套模板 A
- 工作台首页用模板 F + 模板 H 组合
- 经营驾驶舱用模板 F，下钻到明细用模板 A

### 7.11 当前原型模板映射

| 模板 | 原型页面 | 说明 |
|---|---|---|
| A. 列表-筛选-处理 | 线索管理、意向管理、客户 360° 列表、通讯录、任务 | 最常见的业务列表页 |
| B. 详情全景 | 客户 360° 详情 | 客户档案聚合页 |
| C. 流程审批 | 意向审批中心 | 报备审批与冲突裁决 |
| D. 看板/流程跟踪 | 工单看板 | 售后工单状态流转 |
| E. 日历时间轴 | 日历 | 日程与拜访计划 |
| F. 数据驾驶舱 | 经营驾驶舱、工作台 | 业绩监控与待办聚合 |
| G. 表单配置 | 品牌库管理 | 品牌与产品基础配置 |
| H. 信息流/协同 | 消息中心 | 系统通知与协同消息 |

### 7.12 禁止事项

- 禁止所有业务页面都套用模板 A，忽略数据的业务形态
- 禁止详情页没有明确的返回入口
- 禁止看板模板中状态列超过 7 个
- 禁止驾驶舱模板中图表无下钻能力

## 八、组件行为通用规范

### 8.1 按钮层级

| 类型 | 使用场景 | 样式 |
|---|---|---|
| 主按钮 | 页面核心操作 | `btn-primary` |
| 次按钮 | 辅助操作 | `btn-ghost` |
| 文本按钮 | 行内操作 | `text-blue-600 hover:underline` |
| 危险按钮 | 删除、废弃等不可逆操作 | 红色按钮，需二次确认 |

### 8.2 弹窗/抽屉规范

- 弹窗用于表单提交、确认操作
- 抽屉用于详情展示、分步流程
- 点击遮罩或关闭按钮可关闭
- 关闭前如有未保存数据，提示用户

### 8.3 状态标签规范

| 状态类型 | 颜色 |
|---|---|
| 正常/生效/完成 | 绿色 `badge-green` |
| 进行中/审批中/关注 | 橙色/蓝色 `badge-orange` / `badge-blue` |
| 风险/冲突/驳回 | 红色 `badge-red` |
| 草稿/待分配/废弃 | 灰色 `badge-gray` |
| 特殊类型（TP/捐赠） | 紫色 `badge-purple` |

### 8.4 加载状态

- 列表加载：显示骨架屏或加载动画
- 按钮加载：显示加载中状态，防止重复提交
- 详情加载：显示占位内容

### 8.5 反馈提示

- 操作成功：顶部 toast 提示
- 操作失败：明确错误原因
- 确认操作：使用确认弹窗

## 十、版本控制规范

### 10.1 原型版本号

原型 HTML 文件顶部注释必须包含版本号：

```html
<!-- 鑫渠高保真原型 v{x}.{y}.{z} | 更新日期：YYYY-MM-DD | 本次更新：简要说明 -->
```

版本号规则：
- x：主版本，重大重构时更新
- y：次版本，新增模块或重大功能时更新
- z：修订版本，小优化、文案调整、bug 修复时更新

### 10.2 文档版本号

每个 Markdown 文档头部必须包含：

```markdown
> **文档版本**：v{x}.{y}  
> **更新日期**：YYYY-MM-DD  
> **对应原型**：《鑫渠高保真原型.html》v{x}.{y}.{z}
```

文档更新必须：
1. 提升文档版本号
2. 在版本记录表中新增一行
3. 同步更新对应原型版本号

### 10.3 提交规范

提交信息格式：

```
type(scope): 简短描述

- 详细变更点 1
- 详细变更点 2
```

类型：
- `feat`：新功能
- `fix`：bug 修复
- `docs`：文档更新
- `style`：样式调整
- `refactor`：重构

## 十二、设计原则速查

| 原则 | 说明 |
|---|---|
| **信息分层** | 全局 → 导航 → 筛选 → 明细 → 分页 |
| **行动导向** | 每个页面、每张卡片都有明确的下一步动作 |
| **状态驱动** | 操作按钮随对象状态变化 |
| **双态结构** | 列表找目标，详情做深度 |
| **视图适配** | 数据少时看卡片，数据多时看列表 |
| **模板选型** | 按业务形态选择对应布局模板 |
| **一致性** | 同类模块复用相同组件和交互模式 |
| **权限感知** | 不同角色看到不同的数据和操作 |
| **即时反馈** | 搜索、筛选、操作后立即给出反馈 |
| **轻量处理** | 优先用弹窗、抽屉、折叠面板完成操作，减少全页跳转 |
| **可配置** | 流程、字段、视图、权限都支持后台配置 |

## 十三、技术架构（双中台）

### 13.1 架构目标

- 业务能力复用：避免每个应用重复建设客户、产品、订单等基础能力
- 技术能力复用：工作流、权限、消息、文件等通用能力统一沉淀
- 灵活可扩展：新业务流程通过配置而非硬编码实现
- 前后端分离：前端专注交互，后端专注业务与中台能力

### 13.2 双中台分层

```
┌─────────────────────────────────────────────────────────────┐
│ 前端层（鑫渠 CRM）                                           │
│ 工作台 / 应用中心 / 审批中心 / 客户 360° / 日历 / 后台设置   │
├─────────────────────────────────────────────────────────────┤
│ 业务中台                                                     │
│ 客户中心 │ 线索中心 │ 意向中心 │ 订单中心 │ 服务中心        │
```

## 十四、工作流引擎设计

### 14.1 设计目标

- 一个引擎支撑所有业务流程
- 流程模板可配置、可扩展
- 支持自由流（动态加签、转交、指定下一步）
- 审批与业务解耦，通过事件回调驱动业务状态变更

### 14.2 核心模型

| 概念 | 说明 |
|---|---|
| 流程模板（Process Template） | 某类业务的标准审批流程定义 |
| 流程实例（Process Instance） | 一次具体业务发起的流程 |
| 节点（Node/Activity） | 流程中的步骤 |
| 任务（Task） | 当前需要某人处理的待办 |
| 审批规则（Assignee Rule） | 决定任务由谁处理 |
| 审批操作（Action） | 通过、驳回、转交、加签、撤回、催办 |
| 审批历史（History） | 不可变的审批记录 |

### 14.3 节点类型

| 类型 | 用途 |
|---|---|
| start | 流程开始 |
| approval | 单人审批 |
| countersign | 会签（多人全部通过） |
| anysign | 或签（多人任一通过） |
| auto | 自动节点（冲突检测、状态变更） |
| condition | 条件分支 |
| end | 流程结束 |

### 14.4 审批人绑定方式

| 方式 | 说明 | 示例 |
|---|---|---|
| 固定用户 | 指定具体人 | 总经理 |
| 固定角色 | 指定角色 | 销售总监 |
| 直属上级 | 根据申请人动态计算 | 申请人的区域经理 |
| 数据范围规则 | 根据业务对象计算 | 客户所属区域的区域总监 |
| 表达式 | 根据业务字段条件计算 | 金额 > 100万 → 总经理 |
| 动态指定 | 当前审批人指定下一步审批人 | 自由流 |
| 候选组 + 抢单 | 多人可处理，先处理先得 | 售后工程师组 |

### 14.5 自由流设计

自由流不是无规则，而是在规则框架内允许动态调整：

- **转交**：当前审批人把任务交给他人处理
- **加签**：在当前节点前或后插入临时审批人
- **动态指定下一步**：审批人指定下一个审批人
- **驳回到任意节点**：不仅驳回到上一节点，也可到指定历史节点
- **流程模板控制**：哪些节点允许自由流、允许加签、允许转交，由模板配置

### 14.6 可配置能力

| 配置项 | 说明 |
|---|---|
| 可视化流程设计器 | 拖拽节点、连线、设置条件 |
| 节点审批人配置 | 固定 / 角色 / 规则 / 动态 |
| 条件分支配置 | 金额、区域、业务类型等字段驱动 |
| 超时策略 | 提醒、自动转交、自动通过 |
| 表单字段权限 | 每个节点可见/可编辑哪些字段 |
| 通知配置 | 节点到达时通知谁、用什么方式 |
| 业务回调 | 审批结果触发业务状态变更 |
| 版本管理 | 流程模板支持版本，旧实例按旧版运行 |

### 14.7 审批与业务解耦

```
申请人提交业务单据
        │
        ▼
业务系统调用工作流：startProcess(templateCode, businessId, variables)
        │
        ▼
工作流引擎生成任务，通知审批人
        │
        ▼
审批人操作（通过/驳回/转交）
        │
        ▼
工作流引擎推进流程，触发事件
        │
        ▼
业务系统监听事件，更新业务对象状态
```

示例事件：
- `OPPORTUNITY_APPROVAL.APPROVED` → 意向状态变为「生效中」
- `OPPORTUNITY_APPROVAL.REJECTED` → 意向状态变为「被驳回」
- `SAMPLE_APPLICATION.APPROVED` → 样品状态变为「已出库」

### 14.8 IVD 行业特殊控制

| 控制点 | 工作流中的处理 |
|---|---|
| 撞单冲突 | 提交后自动节点检测冲突，冲突则进入裁决分支 |
| 合规风险 | TP/捐赠/样品等业务类型强制加入合规会签节点 |
| 时效管控 | 节点设置 SLA，超时自动提醒、升级或转交 |
| 审计留痕 | 所有审批操作、意见、时间写入不可变历史表 |
| 区域/产品线权限 | 审批人按数据范围过滤任务 |

## 十六、前端工程化规范

### 16.1 技术栈建议

| 层 | 推荐技术 |
|---|---|
| 框架 | Vue 3 + TypeScript |
| 组件库 | Arco Design / Element Plus |
| CSS 方案 | Tailwind CSS + CSS Variables |
| 状态管理 | Pinia |
| 路由 | Vue Router |
| 构建工具 | Vite |
| 图标 | SVG Icon（按需加载） |

### 16.2 自适应布局

- 使用 Flexbox / Grid 布局，避免固定像素宽度
- 容器使用百分比、flex-grow、minmax 等相对单位
- 内容区使用 `min-width: 0` 防止 flex 子项溢出
- 断点规范：大屏 ≥1440px、中屏 1024-1440px、小屏 768-1024px、移动端 <768px
- 页面最小宽度 1280px，低于此宽度出现横向滚动而非破坏布局

### 16.3 按钮与文本规范

```css
/* 按钮不换行 */
.btn {
  white-space: nowrap;
  min-width: fit-content;
  flex-shrink: 0;
}

/* 文本溢出 */
.text-ellipsis {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  min-width: 0;
}
```

- 按钮文字不超过 6 个汉字
- 同一行按钮不超过 3 个
- 重要按钮不能被折叠、遮挡

### 16.4 主题切换

使用 CSS 变量定义颜色：

```css
:root {
  --bg: #F5F6F7;
  --card: #FFFFFF;
  --ink: #1A1D21;
  --sub: #6B7280;
  --line: #E5E7EB;
  --primary: #3370FF;
  --primary-hover: #2E63E8;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #1A1D21;
    --card: #23272F;
    --ink: #F5F6F7;
    --sub: #9CA3AF;
    --line: #374151;
    --primary: #4C88FF;
    --primary-hover: #5A94FF;
  }
}
```

- 所有颜色引用必须使用 CSS 变量
- 阴影、边框、背景色都要随主题变化
- 提供手动切换开关，同时监听系统主题

### 16.5 字体与图标缩放

- 全部使用 `rem` 单位
- 根字体大小：`font-size: clamp(14px, 0.9vw + 8px, 18px)`
- 图标使用 SVG，尺寸也用 rem
- 间距使用 rem 或百分比
- 字号放大 25% 时，页面不应出现遮挡、换行、溢出
- 测试场景：浏览器缩放 125%、150%

### 16.6 性能要求

- 首屏加载 < 3s
- 组件按需加载
- 大数据列表使用虚拟滚动
- 图片懒加载
- 接口请求防抖/节流

## 十七、工作台导航与快速返回

### 17.1 工作台定位

工作台是用户每天的一站式工作入口，不是简单的首页。它聚合：
- 今日待办
- 今日日程
- 关键指标
- 最近访问
- 我的应用
- 消息提醒

### 17.2 从工作台跳转到应用后的快速返回

用户从工作台进入业务应用后，必须能快速回到工作台。采用多层返回机制：

#### 1. 全局返回按钮
- 顶部栏左侧常驻「← 返回工作台」
- 进入业务应用时自动显示
- 点击后回到工作台，保持工作台状态

#### 2. 面包屑导航
- 层级较深页面显示：工作台 / 应用名 / 详情名
- 点击「工作台」直接返回

#### 3. Logo / Home 键
- 点击侧边栏 Logo 或顶部「工作台」标题返回工作台
- 快捷键 `Esc` 或 `⌘/Ctrl + H` 返回工作台

#### 4. 最近访问应用
- 工作台或顶部栏显示最近使用的 3-5 个应用
- 点击切换应用，再次点击工作台返回

#### 5. 右侧抽屉减少全页跳转
- 查看详情优先用右侧抽屉，不离开当前页面
- 编辑表单可用弹窗或抽屉
- 只有需要沉浸式操作时才全页跳转

### 17.3 返回状态保持

- 返回工作台时保留搜索、筛选、分页状态
- 工作台本身的数据刷新但不重置用户操作
- 使用路由状态或本地存储保存临时状态

```
┌─────────────────────────────┐

├─────────────────────────────┤
│                             │
│        内容区域             │  ← 中部：可滚动
│                             │

└─────────────────────────────┘
```

- 圆角：16px（弹窗）、12px（卡片）、0（抽屉边缘贴合）

- 遮罩：`rgba(0,0,0,.45)`（弹窗）、`rgba(0,0,0,.4)`（抽屉）
- 内边距：`p-5`（20px）或 `p-6`（24px）
- 关闭方式：点击关闭按钮、点击遮罩、按 Esc

### 18.5 抽屉规范

- 右侧抽屉宽度固定 480px，支持扩展 640px
- 内容过多时内部滚动，不带动整个页面滚动
- 底部固定操作栏（表单类抽屉）
- 支持堆叠抽屉（最多 2 层）

### 18.6 手风琴规范

- 标题行高度 48px
- 展开/折叠图标统一在右侧
- 同时最多展开 1 个分组（默认）或支持多个展开
- 展开内容使用淡入动画

### 18.7 字号放大适配

- 面板宽度使用 max-width + 自适应，不能写死 px
- 按钮使用 flex-shrink: 0 防止被压缩
- 内容区支持独立滚动
- 标题文字超长时使用 ellipsis

### 18.8 禁止事项

- 禁止弹窗上再弹弹窗（最多一层弹窗 + 一层抽屉）
- 禁止抽屉内容超过一屏且无滚动
- 禁止面板按钮换行或被遮挡
- 禁止不同业务的面板样式不统一

## 十九、前端布局与样式实现规范

> 本章聚焦《鑫渠高保真原型.html》已形成稳定模式的前端实现细节，是设计系统落地到 HTML/CSS/Tailwind 的具体标准。所有新增页面、弹窗、卡片、表格必须按本章执行，避免同类布局缺陷反复出现。

### 19.1 CSS 与 Tailwind 混用规则

原型采用 **Tailwind CSS 工具类 + 自定义 CSS 类** 的混合方案。开发时必须遵守以下优先级：

| 层级 | 用途 | 示例 |
|---|---|---|
| 1. CSS Variables | 颜色、阴影、主题 token | `--primary`, `--bg`, `--shadow-card` |
| 2. 自定义语义类 | 跨页面复用的组件样式 | `.card`, `.btn`, `.kpi-card`, `.data-table` |
| 3. Tailwind 工具类 | 一次性布局微调 | `flex`, `gap-4`, `items-center`, `truncate` |

**强制规则**：
1. 颜色、边框、阴影必须引用 CSS 变量，禁止写死色值。
2. 组件级样式必须封装成语义类，禁止在 HTML 中写长串 Tailwind 类替代 `.card`、`.btn` 等。
3. Tailwind 仅用于局部布局（`flex`, `grid`, `gap`, `p-4` 等）和一次性修饰。
4. 当 Tailwind 工具类与自定义类冲突时，以自定义类为准；必要时用 `!important` 在自定义类中兜底。

**Tailwind 缺失类必须手动补齐**：
原型为单文件 HTML，Tailwind 未包含全部工具类，以下类必须在 `<style>` 中显式定义：

```css
/* 隐藏工具类 */
.hidden { display: none !important; }

/* 栅格列数 */
.grid-cols-4 { grid-template-columns: repeat(4, minmax(0, 1fr)); }
.grid-cols-5 { grid-template-columns: repeat(5, minmax(0, 1fr)); }
.grid-cols-6 { grid-template-columns: repeat(6, minmax(0, 1fr)); }

/* 语义颜色辅助 */
.text-ink   { color: var(--ink); }
.text-sub   { color: var(--sub); }
.border-line       { border-color: var(--line); }
.border-line-light { border-color: var(--line-light); }
```

> 新增页面若使用 `grid-cols-7` 等未定义列数，必须同步补充对应 CSS，否则在原型中不生效。

### 19.5 卡片弹窗与列表手风琴交互规范

#### 19.5.1 双视图交互原则

针对客户 360°、线索管理、意向管理等同时存在卡片视图与列表视图的页面：

| 视图 | 交互模式 | 展开载体 |
|---|---|---|
| 卡片视图 | 点击卡片弹出 **卡片弹窗** | `.intention-modal` + `.card-modal-header` |
| 列表视图 | 点击行展开 **手风琴下拉面板** | `.intention-accordion` + `.intention-accordion-content` |

**核心规则**：
1. 卡片视图时，系统采用弹窗交互模式。
2. 列表视图时，系统采用手风琴下拉式风格。
3. 手风琴下拉面板风格必须参照卡片弹窗风格设计，尽量保持布局一致。
4. 同一页面内，视图切换后交互模式必须同步切换，禁止混用。

#### 19.5.2 手风琴 DOM 结构

```html
<table class="data-table intention-accordion">
  <tbody>
    <tr class="accordion-row" data-id="1">
      <td>行数据 ...</td>
    </tr>
    <tr class="accordion-panel hidden">
      <td colspan="999">
        <div class="intention-accordion-content">
          <!-- 下拉内容：复用弹窗 body 内的布局 -->
        </div>
      </td>
    </tr>
  </tbody>
</table>
```

CSS：

```css
.intention-accordion td { padding: 0; border-bottom: 1px solid var(--line); }
.intention-accordion-content { padding: 20px; }
.accordion-panel { min-height: 0; }
.accordion-panel.hidden { display: none; }
```

展开动画建议：

```css
.accordion-panel {
  display: grid; grid-template-rows: 0fr; transition: grid-template-rows 0.25s ease;
}
.accordion-panel.open { grid-template-rows: 1fr; }
.accordion-panel > td { overflow: hidden; }
```

### 19.7 数据分析类页面布局强制规范

适用页面：经营驾驶舱、效益中心、数据洞察中心、目标绩效、试剂运营、返利与佣金、资质管理、渠道秩序等。

#### 19.7.1 信息分层

```
┌─────────────────────────────────────────────┐
│ 核心 KPI 大图（1-4 个）                      │
├─────────────────────────────────────────────┤
│ 趋势图表 / 漏斗图 / 排行榜 / 对比分析        │
├─────────────────────────────────────────────┤
│ 明细下钻表格 / 预警列表                      │
├─────────────────────────────────────────────┤
│ AI 分析结论区域（必须置于页面底部）          │
└─────────────────────────────────────────────┘
```

#### 19.7.2 图表与 KPI 尺寸自适应

- 图表容器使用相对高度（如 `min-height: 300px`），禁止写死 px 导致挤压变形。
- 多列布局优先使用 `grid-template-columns: repeat(auto-fit, minmax(320px, 1fr))`，根据内容自动换行。
- 避免在同一行内强制塞入过多 KPI，导致数字过大或过小。
- 业绩预测、缺口分析等模块如果内容拥挤，应单独占一行或扩大最小宽度，禁止挤压变形。

#### 19.7.3 AI 结论区域（底部固定）

所有 AI 生成的分析结论、归因、风险预警、经营建议、行动建议，必须放在页面主体数据的最下方。

```html
<div class="card p-4 mb-5">
  <div class="flex items-center gap-2 mb-4">
    <svg class="icon icon-md text-primary"><use href="#icon-ai"/></svg>
    <h3 class="font-semibold text-ink">AI 分析结论</h3>
  </div>
  <div class="grid grid-cols-1 md:grid-cols-3 gap-4 mb-4">
    <div class="p-4 rounded-lg bg-success-bg">...</div>
    <div class="p-4 rounded-lg bg-warning-bg">...</div>
    <div class="p-4 rounded-lg bg-danger-bg">...</div>
  </div>
  <div class="p-3 rounded-lg bg-panel">
    <div class="text-sm font-medium text-ink mb-2">经营建议</div>
    <div class="text-sm text-sub">1. ... 2. ... 3. ...</div>
  </div>
</div>
```

### 19.8 漏斗图与销售漏斗展示规范

销售漏斗等转化分析必须使用漏斗形状图标，形象展示各阶段转化对比：

- 使用 SVG 绘制漏斗层级，上宽下窄。
- 每个阶段使用不同透明度或色阶区分。
- 阶段宽度与数量/金额成正比，直观体现漏斗粗细变化。
- 右侧或下方列出各阶段名称、数量、转化率。

禁止用普通柱状图或表格替代漏斗图。

### 19.9 常见布局缺陷与修复清单

| 缺陷 | 正确做法 | 相关类 / 属性 |
|---|---|---|
| 弹窗标题前出现「线：」「客：」等前缀 | 删除前缀，标题直接显示对象名称 | `.card-modal-title-row` |
| 关闭按钮位置偏移或跑到标题左侧 | 关闭按钮必须位于头部右上角 | `justify-content: space-between` |
| KPI 被挤压变形 | 使用 `auto-fill` 或单独占行，避免强制多列 | `.kpi-grid` |
| 回款达成率等 KPI 数字过大 | 统一 KPI 数值字号，避免异常放大 | `.kpi-value` |
| 经营驾驶舱图表挤压 | 图表容器用 `min-height` + `auto-fit` | `.chart-placeholder` |
| 弹窗内出现业务无关占位文字 | 清理所有占位，替换为真实字段 | 数据字段 |
| 合规证据链等总计项换行 | 总计项应在一行内横向排列 | `flex`, `gap-3` |
| 数据分析结论放在页面上方 | 必须放在页面底部 | 见 19.7.3 |
| 列表视图仍使用弹窗 | 列表视图用手风琴，卡片视图用弹窗 | 见 19.5 |
| 页面缺少 Tab（如线索管理的我的/公海/团队） | 必须补齐所有业务状态 Tab | `.tab` |
| Tailwind `grid-cols-4/5/6` 不生效 | 手动补齐 CSS 定义 | 见 19.1 |

### 19.10 禁止事项

- 禁止在代码中写死颜色值（必须使用 CSS 变量）。
- 禁止弹窗标题前加业务对象前缀文字。
- 禁止关闭按钮漂浮到标题左侧或下方。
- 禁止 KPI 卡片在同一行内被挤压到不可读。
- 禁止数据分析类页面的 AI 结论区域前置。
- 禁止列表视图与卡片视图混用同一种交互模式。
- 禁止漏斗图用柱状图/表格替代。
- 禁止新增栅格列数不补充对应 CSS。
- 禁止页面内容区缺少 `min-width: 0`。
