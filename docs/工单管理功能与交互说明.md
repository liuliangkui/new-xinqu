## 二、模块定位与目标

### 2.1 模块定位

工单管理是鑫渠 CRM「业务管理域」的**服务履约中枢**，连接客户报修、服务调度、工程师现场服务、备件耗材、满意度评价与知识沉淀。它以 IVD 设备运维为核心场景，将售后请求从「人工电话/微信救火」升级为「流程化、可追踪、可度量」的数字化服务闭环。

### 2.2 核心定位一句话

> 工单管理是 IVD 企业面向客户提供**可承诺、可追踪、可评价**的现场服务履约平台，核心通过**智能派单**与**SLA 全程监控**保障服务时效与服务质量。

### 2.3 解决的核心问题

- 报修渠道杂乱，信息遗漏、责任不清。
- 派单依赖人工经验，效率低且分配不均。
- 服务进度不可见，客户/销售/管理层反复询问。
- SLA 缺乏监控，超时无预警。
- 服务数据未沉淀，故障方案无法复用。
- 客户满意度难量化，服务质量无法闭环改进。

## 三、业务场景与角色

### 3.1 使用角色

| 角色 | 核心职责 | 典型操作 |
|---|---|---|
| 客户/医院用户 | 发起服务请求、确认服务完成、评价服务 | 提交报修、上传故障图片、确认到场、填写满意度 |
| 销售代表 | 代客报修、跟进服务进度 | 代提交工单、查看进度、协调客户时间 |
| 售后工程师 | 接收工单、现场服务、反馈处理结果 | 接单、到场打卡、录入故障与方案、申请备件 |
| 服务主管/调度员 | 工单分派、资源协调、异常督办 | 派单、改派、催办、关闭争议工单 |
| 服务经理 | 服务质量管理、SLA 监控、团队绩效 | 查看 SLA 看板、分析超时工单 |
| 厂家技术支持 | 提供远程技术支持、复杂故障会诊 | 远程接入、出具技术意见 |
| 备件管理员 | 备件出库、库存管理、物流跟踪 | 审批备件申请、发运备件、确认签收 |

### 3.2 典型业务场景

| 场景 | 触发方式 | 处理角色 | 关键动作 |
|---|---|---|---|
| 设备故障报修 | 客户小程序/销售代报/400 客服录入 | 服务主管派单 → 工程师上门 | 接单、到场、维修、客户确认 |
| 定期保养 | 系统按保养计划自动生成 | 服务主管派单 → 工程师执行 | 到场打卡、保养项检查、生成报告 |
| 巡检服务 | 按年度巡检计划生成工单 | 工程师按工单逐项检查 | 拍照、记录、异常转维修工单 |
| 安装培训 | 设备装机后自动生成培训任务 | 工程师/培训师上门 | 培训签到、考核、提交报告 |
| 加急工单插队 | 关键客户设备宕机 | 服务主管 | 在看板中标记紧急并拖拽至指定工程师 |
| SLA 超时预警 | 系统自动标红剩余时间不足/已超时工单 | 服务主管/区域总监 | 主动介入、改派、加人 |

## 五、业务流程

### 5.1 标准报修派单流程

```
客户/销售提交报修
    │
    v
系统校验：设备档案、保内/保外、重复报修
    │
    v
服务主管审核 / 系统自动派单
    │
    v
工程师接单并响应（SLA 开始计时）
    │
    v
工程师到场打卡（到场 SLA 计时截止）
    │
    v
故障诊断与维修
    │
    ├── 需备件 → 申请备件 → 备件出库 → 签收 → 更换
    │
    ├── 需远程支持 → 申请技术支持 → 远程会诊
    │
    └── 现场解决 → 录入处理方案
    │
    v
客户确认服务完成
    │
    v
客户填写满意度评价
    │
    v
工单关闭，数据沉淀至知识库
```

### 5.2 SLA 超时预警与升级流程

```
工单进入某 SLA 节点
    │
    v
系统实时计算剩余时间
    │
    ├── 剩余 50% 时间 → 黄色预警推送给工程师
    │
    ├── 剩余 20% 时间 → 橙色预警推送给工程师 + 服务主管
    │
    └── 已超时 → 红色预警推送给工程师 + 服务主管 + 服务经理
                │
                v
        服务主管介入：改派、催办、升级、协调资源
                │
                v
        服务经理每日 reviewing 超时工单清单
```

### 5.3 保养计划自动派单流程

```
系统按设备保养周期生成保养工单
    │
    v
根据设备所在区域与工程师技能自动派单
    │
    v
工程师确认保养时间窗口
    │
    v
到场执行保养检查项
    │
    v
拍照/扫码记录关键检查点
    │
    v
生成保养报告并推送客户
    │
    v
客户电子签收，工单关闭
```

### 5.4 统一工单状态流转表

> 说明：「处理中」为复合状态，可叠加「到场/远程支持/备件等待/挂起」等子状态标签；挂起期间暂停 SLA 计时。

| 当前状态 | 触发条件/操作 | 下一状态 | 通知对象 |
|---|---|---|---|
| 待派单 | 客户/销售/客服提交报修，系统校验通过 | 待派单 | 服务主管、客户 |
| 待派单 | 服务主管派单或系统自动派单成功 | 已派单 | 负责工程师、客户、销售代表 |
| 已派单 | 工程师点击「接单」或首次响应 | 处理中 | 服务主管、客户 |
| 已派单 | 工程师拒单、超时未响应或客户改期 | 待派单 | 服务主管、客户 |
| 处理中 | 工程师到场打卡，定位校验通过 | 处理中（已到场） | 客户、服务主管 |
| 处理中 | 工程师申请远程技术支持并获批 | 处理中（远程支持中） | 厂家技术支持、服务主管、客户 |
| 处理中 | 工程师申请备件，审批通过并发运 | 处理中（备件等待中） | 备件管理员、客户、服务主管 |
| 处理中 | 因客户原因/备件未到申请挂起，审批通过 | 处理中（已挂起，暂停 SLA） | 客户、服务主管 |
| 处理中 | 工程师录入处理结果并提交客户确认 | 待确认 | 客户、销售代表、服务主管 |
| 待确认 | 客户确认服务完成 | 已完成 | 工程师、服务主管 |
| 待确认 | 客户对结果有异议或问题未解决 | 处理中 | 工程师、服务主管 |
| 已完成 | 客户填写满意度评价 | 已关闭 | 服务主管、工程师 |
| 已完成 | 评价超时未填写（系统默认关闭） | 已关闭 | 服务主管 |
| 任意非关闭状态 | 客户取消/重复报修/无法解决/误报 | 已关闭 | 服务主管、客户、工程师 |
| 已关闭 | 复核发现重复报修、误关闭或需 reopen | 已驳回 / 待派单 | 服务主管、工程师、客户 |

> 状态枚举必须遵循《鑫渠统一状态机规范.md》中的通用基线：
> - 待派单 = `PENDING`
> - 已派单 = `DISPATCHED`
> - 处理中 = `PROCESSING`
> - 待确认 = `PENDING_CONFIRM`
> - 已完成 = `COMPLETED`
> - 已关闭 = `CLOSED`
> - 已挂起 = `SUSPENDED`（处理中子状态）

> 并发控制：同一工单同一时刻只允许一个生效操作；操作前校验工单版本号，若已被其他用户处理则返回「工单状态已变更，请刷新后重试」。

### 6.2 工单列表页（五层架构）

工单列表页采用自上而下的五层信息架构，让用户从宏观到微观逐步聚焦。

#### 第一层：全局指标（统计卡片）

| 指标 | 说明 |
|---|---|
| 今日待派单 | 已提交但尚未分配工程师的工单数量 |
| 处理中超时 | 当前处理中且已超出 SLA 的工单数量 |
| 今日待上门 | 已派单且预约今日到场的工单数量 |
| 本月满意度 | 本月已完成工单的客户满意度平均分 |
| SLA 达标率 | 本月闭环工单中按时完成的比例 |

#### 第二层：流程导航与操作（Tab + 视图切换 + 主操作）

| 区域 | 内容 |
|---|---|
| Tab 标签组 | 全部 / 待派单 / 处理中 / 待确认 / 已关闭 / 我的工单 / 超时预警 |
| 视图切换 | 列表视图 / 卡片视图 / 地图视图 |
| 主操作 | 「+ 新建工单」按钮 |

#### 第三层：搜索与筛选

| 筛选条件 | 说明 |
|---|---|
| 工单编号/客户名称/设备序列号 | 模糊搜索 |
| 工单类型 | 故障报修 / 保养 / 巡检 / 安装培训 / 投诉 / 耗材配送 |
| 工单状态 | 待派单 / 已派单 / 处理中 / 待确认 / 已完成 / 已关闭 |
| 紧急程度 | 紧急 / 高 / 中 / 低 |
| 服务工程师 | 按工程师筛选 |
| 时间范围 | 提交时间 / 期望上门时间 |
| 区域 | 按客户所在省/市筛选 |

#### 第四层：数据明细（卡片网格 / 表格 / 地图）

**列表视图字段（每页 12 条）**：

| 字段 | 说明 |
|---|---|
| 工单编号 | 系统生成唯一编号，如 GD-20260729-001 |
| 客户 | 医院/医疗机构名称 |
| 设备 | 设备型号 + 序列号 |
| 类型 | 故障报修 / 保养 / 巡检 / 培训 / 投诉 / 耗材 |
| 紧急程度 | 紧急 / 高 / 中 / 低，颜色区分 |
| SLA 剩余 | 当前节点剩余时间，超时显示红色倒计时 |
| 工程师 | 当前负责工程师 |
| 状态 | 当前工单状态 |
| 提交时间 | 工单创建时间 |
| 操作 | 派单 / 详情 / 催办 / 改派 / 关闭 |

**卡片视图字段（每页 8 条，4 列网格）**：

- 工单编号
- 客户名称 + 医院等级
- 设备型号 + 序列号
- 工单类型标签
- 故障摘要
- 紧急程度标签
- SLA 剩余时间（红色表示已超时）
- 服务工程师
- 状态标签
- 操作按钮

**地图视图**：
- 在地图上展示工程师当前位置与待上门工单位置
- 支持按区域、时间窗口筛选
- 点击工单气泡可快速派单或查看详情

#### 第五层：分页与批量操作

| 元素 | 说明 |
|---|---|
| 分页 | 上一页 / 页码 / 下一页 / 当前页/总页数 / 总条数 |
| 批量操作 | 批量派单、批量催办、批量导出（服务主管权限） |

**默认规则**：工单总数 ≤20 时默认卡片视图，>20 时默认列表视图；服务主管默认进入「待派单」Tab，工程师默认进入「我的工单」Tab。

### 6.3 工单看板页

看板页是工单管理的另一种视图形态，核心体验是「看板视图 + 拖拽」。

#### 整体布局

```
┌─────────────────────────────────────────────────────────────────────┐
│  工单看板                                          [+ 新建工单]      │
├─────────────────────────────────────────────────────────────────────┤
│  待处理 │ 处理中 │ 今日到期 │ 已超时 │ 今日关闭                    │
├─────────────────────────────────────────────────────────────────────┤
```

#### 看板拖拽规则

| 拖拽动作 | 触发结果 | 校验与反馈 |
|---|---|---|
| 卡片在同一泳道内上下移动 | 调整排序，代表处理优先级 | 实时保存排序 |
| 卡片从「待派单」拖至「已派单」 | 触发派单，需选择负责人 | 弹出派单确认弹窗 |
| 卡片从「已派单」拖至「处理中」 | 工程师开始处理 | 校验是否为当前负责人 |
| 卡片从「处理中」拖至「待确认」 | 提交处理结果 | 校验是否已填写处理记录 |
| 卡片从「待确认」拖至「已关闭」 | 关闭工单 | 校验客户/主管确认结果 |
| 卡片从任意状态拖至工程师头像区 | 变更负责人 | 弹出确认，同时状态可能变化 |

## 八、交互设计要点

### 8.1 搜索筛选

| 要点 | 说明 |
|---|---|
| 实时搜索 | 输入工单编号、客户名称、设备序列号后 300ms 自动触发搜索 |
| 组合筛选 | 多个筛选条件同时生效，结果实时更新 |
| 筛选记忆 | 用户离开页面后返回，保留上次筛选状态 |
| 重置按钮 | 一键清空所有筛选条件 |
| 筛选结果计数 | 筛选后顶部显示「共 N 条结果」 |

### 8.2 视图切换

| 视图 | 适用场景 |
|---|---|
| 列表视图 | 工单数量多，需批量扫描与操作 |
| 看板视图 | 主管日常监控、派单、拖拽调度 |
| 地图视图 | 服务主管派单时查看工程师位置与工单分布 |

- 切换视图后分页自动重置到第 1 页。
- 不同角色可设置默认视图偏好。

### 8.3 操作反馈

| 场景 | 反馈方式 |
|---|---|
| 提交工单成功 | Toast 提示 + 跳转工单详情 |
| 派单成功 | Toast 提示 + 工程师收到推送通知 |
| 改派成功 | 原工程师与新工程师均收到通知，工单时间线记录改派原因 |
| 到场打卡成功 | 显示「已到场」，SLA 到场计时停止 |
| 备件申请提交 | 显示审批中状态，备件管理员收到待办 |
| 客户确认完成 | 触发满意度评价弹窗 |
| 操作失败 | 明确错误提示，如「该工单已被其他工程师接单」 |

### 8.4 SLA 倒计时展示

- 工单卡片/列表中以颜色区分 SLA 状态：
  - 绿色：剩余时间充足
  - 黄色：剩余时间不足 50%
  - 橙色：剩余时间不足 20%（或不足 4 小时）
  - 红色：已超时

## 十一、未考虑到的问题补充（开发者视角）

1. **看板性能**：当单泳道工单数量超过 100 条时，看板渲染与拖拽性能可能下降，是否启用虚拟滚动或分页加载？
2. **并发操作**：多个主管同时拖拽同一张工单时，如何处理冲突？是否加乐观锁或操作版本号？
3. **SLA 计算精度**：SLA 是否排除非工作时间？挂起期间是否暂停计时？是否需要配置工作日历？
4. **消息推送边界**：超时预警推送频率如何控制，避免对主管造成消息轰炸？
5. **移动端适配**：看板视图在移动端如何展示？是否仅展示「我的待办」列表？
