## 一、总体设计哲学

### 1.1 核心原则：从「看数据」到「做决策」

鑫渠 CRM 的页面布局不是把数据平铺出来，而是**围绕一线销售和管理者的工作流，帮助他们快速做出下一步行动决策**。

每个页面都遵循一个基本问题：**用户打开这个页面，最想干什么？**

- 打开客户 360° → 找到重点客户，判断要不要拜访
- 打开线索管理 → 看到需要分配/跟进的线索
- 打开意向管理 → 看到待审批/待推进的意向
- 打开日历 → 知道今天要见谁、谈什么

### 1.2 统一的信息分层

尽管不同模块业务不同，但页面结构遵循统一的信息分层：

```
┌─────────────────────────────────────┐
│ 第一层：全局指标 / 统计卡片          │  ← 先看整体
├─────────────────────────────────────┤
│ 第二层：导航 / 分类 / 视图切换       │  ← 再定位范围
├─────────────────────────────────────┤
│ 第三层：搜索 / 筛选                 │  ← 快速找到目标
├─────────────────────────────────────┤
│ 第四层：明细内容（卡片/表格）        │  ← 查看具体数据
├─────────────────────────────────────┤
│ 第五层：分页 / 加载更多             │  ← 浏览更多数据
└─────────────────────────────────────┘
```

### 1.3 双态结构：列表是入口，详情是深度操作

有数据列表的模块（客户 360°、线索管理、意向管理）统一采用「列表页 → 详情页」双态：

- **列表页**：快速扫描、筛选、定位，解决「找什么」
- **详情页**：深度查看、多维数据、具体行动，解决「做什么」

### 1.4 卡片即决策单元

卡片/列表行不是信息容器，而是**决策单元**。每张卡片上显示的信息和操作按钮，都服务于一个目的：**让用户不点进详情，就能判断这条记录当前状态下最该做什么**。

## 二、各模块布局对照

### 2.1 客户 360°

| 页面 | 核心目的 | 信息分层 |
|---|---|---|
| 列表页 | 找到重点客户 | 统计卡片 → 快捷筛选 → 搜索筛选 → 客户卡片/表格 → 分页 |
| 详情页 | 深度运营客户 | 头部信息+快捷操作 → 6 个页签 → 页签内容 |

**卡片定位**：客户档案封面，引导用户进入详情。

### 2.2 线索管理

| 页面 | 核心目的 | 信息分层 |
|---|---|---|
| 列表页 | 快速分拣线索 | 统计卡片 → Tab 分组 → 搜索筛选 → 线索卡片/表格 → 分页 |
| 详情页 | 跟进、分配、转意向 | 基本信息 → 跟进时间线 → 操作按钮 |

**卡片定位**：分拣台，按状态决定归属或跟进动作。

### 2.3 意向管理

| 页面 | 核心目的 | 信息分层 |
|---|---|---|
| 列表页 | 推进审批流程 | 统计卡片 → Tab 分组 → 搜索筛选 → 意向卡片/表格 → 分页 |
| 详情页 | 审批、跟进、查看流程 | 项目信息 → 审批时间线 → 操作按钮 |

**卡片定位**：流程节点看板，每个状态对应一个处理动作。

### 2.4 日历

| 页面 | 核心目的 | 信息分层 |
|---|---|---|
| 主页面 | 管理日程安排 | 小月历 → 日期选择器 → 当天日程列表 |

**设计特点**：左侧时间视图，右侧任务视图，顶部选日期。

## 三、组件模式库

### 3.1 统计卡片（KPI Card）

**用途**：展示当前页面的核心指标，让用户一眼把握全局。

**出现位置**：客户 360°、线索管理、意向管理、日历、经销商协同等列表页顶部。

**设计要点**：
- 不超过 5 个，避免信息过载
- 关键指标用颜色区分（红色表风险、绿色表健康、蓝色表进行中）
- 数字大而醒目，标签小而清晰

### 3.2 Tab 标签组

**用途**：按状态/范围/类型分流数据。

**出现位置**：
- 线索管理：全部 / 我的线索 / 公海池 / 团队线索
- 意向管理：全部 / 草稿 / 审批中 / 生效中 / 已结束 / 被驳回

**设计要点**：
- Tab 顺序按业务流程排列
- 当前 Tab 高亮显示
- 切换后分页重置到第 1 页

### 3.3 视图切换按钮组

**用途**：让用户在「概览视图」和「效率视图」之间切换。

**出现位置**：客户 360°、线索管理、意向管理。

**设计要点**：
- 默认智能选择：数据量 ≤20 用卡片，>20 用列表
- 按钮选中态清晰区分
- 切换后保留当前筛选条件

### 3.4 搜索 + 筛选栏

**用途**：快速缩小数据范围。

**设计要点**：
- 搜索框常驻，支持模糊搜索
- 筛选条件按业务维度设计（区域、等级、状态、时间等）
- 筛选结果实时更新

### 3.5 卡片网格

**用途**：信息密度适中，适合做概览和重点识别。

**设计要点**：
- 4 列布局，一屏展示 8 张卡片
- 顶部或左上角显示状态标签
- 关键信息突出（金额、健康度、倒计时）
- 底部或悬停显示操作按钮

### 3.6 数据表格

**用途**：信息密度高，适合批量处理和快速扫描。

**设计要点**：
- 表头固定，内容滚动
- 行悬停高亮
- 操作列放在最右侧
- 支持文字超长悬停滚动

### 3.7 分页组件

**用途**：控制大数据量下的浏览效率。

**设计要点**：
- 显示当前页/总页数/总条数
- 切换视图/筛选/Tab 后重置到第 1 页
- 页码数量适度，避免过长

### 3.8 详情页头部

**用途**：明确当前对象身份，提供高频快捷操作。

**设计要点**：
- 左侧：返回按钮 + 对象名称 + 关键标签
- 右侧：高频操作按钮（拜访、新建意向、提交工单、添加联系人）

### 3.9 页签导航

**用途**：在单一对象下切换不同维度视图。

**出现位置**：客户 360° 详情页（概览/科室/决策链/设备地图/试剂账本/时间线）。

**设计要点**：
- 页签名称清晰反映维度
- 当前页签下划线高亮
- 页签内容独立加载

### 3.10 时间线

**用途**：按时间倒序展示对象的全部交互记录，支撑追溯和合规。

**出现位置**：客户 360° 时间线页、意向详情页、线索详情页。

**设计要点**：
- 用颜色区分事件类型
- 显示时间、操作人、内容摘要
- 支持按类型筛选

## 四、卡片设计的共同语言

### 4.1 卡片 = 对象 + 状态 + 下一步动作

无论哪个模块，卡片都遵循这个公式：

```
卡片内容 = 对象标识 + 当前状态 + 辅助信息 + 最可能的下一步操作
```

### 4.2 为什么不同模块卡片操作不同？

| 模块 | 卡片核心问题 | 典型操作 |
|---|---|---|
| 客户 360° | 要不要深入看？ | 查看、预约拜访、新建意向 |
| 线索管理 | 分给谁/要不要跟进？ | 分配、领取、跟进、查看 |
| 意向管理 | 当前流程节点该谁处理？ | 审批、裁决、跟进、重新提交 |

操作不同不是因为设计不统一，而是因为**业务对象的生命周期和核心问题不同**。

### 4.3 操作按钮的设计原则

1. **状态驱动**：同一对象在不同状态下，操作按钮不同
2. **单一主操作**：每张卡片只保留 1-2 个最常用操作
3. **避免歧义**：按钮文案直接说明动作结果（如「分配」而非「操作」）
4. **权限感知**：不同角色看到不同的操作按钮

## 六、后续设计完善建议

### 6.1 全局体验增强

1. **全局搜索/命令面板（Cmd+K）**
   - 支持快速跳转客户、意向、设备、联系人
   - 支持快捷操作：「新建意向」「预约拜访」

2. **最近访问 / 收藏夹**
   - 工作台显示最近查看的客户/意向
   - 支持收藏重点客户，快速回访

3. **消息通知中心**
   - 审批提醒、预警提醒、任务到期提醒统一入口
   - 支持一键跳转处理

4. **面包屑导航**
   - 客户 360° 详情页、科室 360° 子页面增加面包屑
   - 方便用户知道当前位置并快速返回

### 6.2 列表页体验增强

5. **表头排序**
   - 列表视图支持点击表头排序（金额、时间、健康度等）
   - 默认排序规则可配置

6. **批量操作**
   - 线索管理、意向管理列表支持勾选多行批量分配/审批/导出
   - 客户 360° 支持批量打标签

7. **自定义显示字段**
   - 列表视图允许用户自定义显示哪些列
   - 保存个人视图偏好

8. **空态优化**
   - 无数据时给出引导操作（如「录入第一条线索」）
   - 空态页面配图 + 文案 + 操作按钮

### 6.3 详情页体验增强

9. **Inline 编辑**
   - 客户基本信息、联系人信息支持点击即编辑
   - 减少弹窗切换

10. **关联对象快速跳转**
    - 意向详情中的客户名可跳转客户 360°
    - 设备详情中的试剂可跳转试剂账本

11. **审批流程可视化**
    - 意向详情页用流程图展示当前审批节点
    - 标红阻塞节点，显示处理人

### 6.4 移动端体验增强

12. **移动端卡片优化**
    - 卡片在窄屏下改为单列或双列
    - 操作按钮改为底部固定栏

13. **语音录入**
    - 拜访记录、线索摘要支持语音转文字
    - 适合一线在医院场景快速录入

### 6.5 智能化增强

14. **AI 客户摘要**
    - 客户 360° 概览页用 AI 生成一段客户运营摘要
    - 提示风险、机会、下一步建议

15. **智能推荐**
    - 基于客户画像推荐最佳拜访时间
    - 基于历史数据推荐跟进话术

### 6.6 合规与审计增强

16. **操作留痕升级**
    - 所有写操作记录完整前后值对比
    - 支持导出审计报告

17. **敏感数据脱敏提示**
    - 经销商查看联系人时明确提示「已脱敏」
    - 查看敏感数据时二次确认

## 七、设计原则速查

| 原则 | 说明 |
|---|---|
| **信息分层** | 全局 → 导航 → 筛选 → 明细 → 分页 |
| **行动导向** | 每个页面、每张卡片都有明确的下一步动作 |
| **状态驱动** | 操作按钮随对象状态变化 |
| **双态结构** | 列表找目标，详情做深度 |
| **视图适配** | 数据少时看卡片，数据多时看列表 |
| **一致性** | 同类模块复用相同组件和交互模式 |
| **权限感知** | 不同角色看到不同的数据和操作 |
