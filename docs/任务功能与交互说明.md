## 机器指令块

开发本模块前，AI 必须先读取并遵守以下全局约束：

- **技术栈**：Vue 3 + TypeScript + Pinia + Vue Router + Ant Design Vue 4.x + Tailwind CSS
- **组件库**：必须使用《鑫渠组件库清单与命名规范.md》v1.0 中注册的组件名，禁止自行发明组件名
- **图标**：全部使用 SVG 图标或 Iconfont，禁止引用 PNG/JPG 图标
- **样式变量**：颜色、字号、间距必须使用《鑫渠全局设计系统规范.md》中的 CSS 变量
- **响应式断点**：
  - PC 宽屏：>=1440px
  - PC 标准：1024px-1439px
  - 平板：768px-1023px
  - 移动端：<768px
- **权限模型**：基于 RBAC + 数据范围，角色编码见《华鑫角色职责与用户故事.md》
- **数据规范**：字段命名必须与本文档「核心字段规范」完全一致
- **接口规范**：接口路径、字段命名必须与本文档「接口契约」完全一致
- **验收标准**：开发完成后必须对照本文档「验收断言清单」逐项验证

## 一、模块定位与目标

### 1.1 一句话定位
任务管理是鑫渠 CRM 的工作执行与协作跟踪域入口，支撑任务的下发、认领、推进、完成、提醒与逾期预警，确保销售与售后服务动作按计划落地。

### 1.2 业务痛点
- 销售日常工作事项分散在聊天、邮件、备忘录中，容易遗漏关键跟进节点
- 主管无法实时掌握团队成员任务完成情况和逾期风险
- 与客户、意向、工单等核心业务对象关联弱，任务上下文缺失
- 任务状态变更缺少留痕，难以进行绩效复盘
- 移动端拜访场景下，缺少便捷的任务完成入口

### 1.3 量化价值
- 任务逾期率下降 30% 以上
- 销售每日关键动作完成率提升 25% 以上
- 主管查看团队任务状态耗时减少 50% 以上
- 任务与客户 360°、意向、工单关联后，上下文切换次数减少 40% 以上

### 1.4 所属业务域
渠道协同域 / 工作执行域，与消息中心、日历、客户 360°、意向管理、售后工单深度耦合。

### 1.5 典型业务场景

| 场景编号 | 角色 | 场景描述 | 达成目标 |
|---|---|---|---|
| S1 | 销售代表 | 销售代表在客户拜访前收到系统生成的「XX 医院年度合同续签提醒」任务，点击查看关联客户档案后完成拜访，并在系统中标记任务完成 | 关键跟进节点不遗漏，客户续约动作按时推进 |
| S2 | 销售主管 | 销售主管月初给团队下派本月重点客户拜访任务，指定负责人和截止时间，并在工作台查看团队任务完成率 | 团队工作可量化分配，执行进度实时可见 |
| S3 | 售后工程师 | 售后工程师收到「XN-550 保修续签」协作任务，上传续签协议附件并更新进度为 100%，任务自动同步到关联工单 | 服务类任务闭环，附件和进度留痕 |
| S4 | 区域经理 | 区域经理发现某销售负责的多条任务已逾期，批量催办并重新调整优先级和截止时间 | 逾期风险及时干预，资源重新分配 |

### 2.3 数据范围
- 销售代表：可查看自己负责或参与的任务，以及可领取的公开协作任务
- 销售主管：可查看本部门及下属所有任务
- 区域经理：可查看本区域及所有子区域任务
- 售后工程师：可查看分配给自己的售后类任务和本人创建的任务
- 系统管理员：可查看全部任务，但不可越权完成他人任务

## 四、核心业务流程

### 4.1 流程一：任务下发与执行

**流程目标**：完成从任务创建到任务关闭的完整生命周期管理。
**参与角色**：任务创建人、负责人、参与人、主管。

#### 流程图

```
开始
  |
  v
新建任务 --(校验失败)--> 提示并停留表单
  | (校验通过)
  v
待处理状态
  |
  |-- 负责人领取/创建人指派 --> 进行中
  |
  v
进行中 --(更新进度/上传附件)--> 进行中
  |
  |-- 负责人标记完成 --> 已完成
  |-- 任务取消/关闭 --> 已关闭
  |-- 截止时间到期未完成 --> 已逾期
  v
结束
```

#### 步骤表

| 步骤 | 角色 | 操作 | 系统校验 | 输出 |
|---|---|---|---|---|
| 1 | 创建人 | 点击「新建任务」 | 校验新建权限 | 打开新建抽屉 |
| 2 | 创建人 | 填写任务名称、类型、优先级、关联对象、负责人、参与人、截止时间、备注 | 校验必填项、格式、负责人是否存在 | 表单高亮错误 |
| 3 | 创建人 | 点击「保存」或「保存并派发」 | 校验权限范围 | 任务进入「待处理」状态 |
| 4 | 负责人 | 在列表或详情中领取/接受任务 | 校验负责人身份 | 状态变为「进行中」 |
| 5 | 负责人 | 更新进度、填写跟进记录、上传附件 | 校验可编辑权限 | 时间线新增记录 |
| 6 | 负责人 | 点击「标记完成」 | 校验完成权限、必填完成说明 | 状态变为「已完成」 |
| 7 | 系统 | 到达截止时间未完成的任务 | 自动标记为「已逾期」 | 触发消息提醒 |

#### 异常分支表

| 异常场景 | 触发条件 | 处理方式 | 页面反馈 |
|---|---|---|---|
| 负责人离职或禁用 | 保存时负责人账号失效 | 提示重新选择负责人 | 表单字段红色高亮 |
| 关联对象被删除 | 客户/意向等关联对象已删除 | 保留历史关联名称但标记「已删除」 | 详情页显示灰色文字 |
| 任务被取消 | 创建人主动取消 | 状态变为「已关闭」，不可编辑 | 操作按钮隐藏 |
| 任务已逾期 | 超过截止时间且未完成 | 状态标签变为红色，置顶显示 | 列表页按逾期时间排序 |
| 越权访问 | 用户无该任务查看权限 | 跳转 403 或无权限空态 | 显示「无权查看」 |

### 4.2 流程二：任务协作与指派

**流程目标**：支持团队内任务派发、参与人协同、主管督办。
**参与角色**：主管、负责人、参与人。

#### 流程图

```
主管选择「派发任务」
    |
    v
填写任务信息并指定负责人
    |
    v
系统通知负责人
    |
    v
负责人接受 --> 进行中
    |
    |-- 负责人转交 --> 待处理（新负责人）
    |
    v
参与人评论/上传附件
    |
    v
主管督办/催办
    |
    v
任务完成
```

#### 状态流转表

| 状态编码 | 状态名称 | 可执行操作 | 下一状态 | 触发条件 |
|---|---|---|---|---|
| 0 | 待处理 | 编辑、删除、领取、分配、取消 | 1/3/4 | 负责人领取/指派/取消 |
| 1 | 进行中 | 编辑、更新进度、上传附件、转交、标记完成、取消 | 2/3/4 | 完成/取消/转交 |
| 2 | 已完成 | 查看、重启、导出 | 1 | 创建人或主管点击重启 |
| 3 | 已关闭 | 查看、导出 | - | 流程闭环 |
| 4 | 已逾期 | 查看、更新进度、标记完成、关闭、重新指派 | 2/3 | 完成/关闭 |

### 6.1 任务列表页


#### PC 端布局

- **容器**：使用 XqPageLayout 组件，showStats=true，showFilter=true
- **标题区**：左侧显示「我的任务」标题，右侧使用 button 标签 class="btn-primary" 显示「新建任务」
- **统计卡片区**：使用 4 个 XqKpiCard 组件横向排列，指标为待处理、进行中、已完成、已逾期
  - 待处理：橙色
  - 进行中：蓝色
  - 已完成：绿色
  - 已逾期：红色
- **导航/操作区**：左侧使用 XqNavTabs 组件显示 Tab（全部、我的任务、团队任务、已逾期），右侧使用 XqViewSwitch 组件切换卡片/列表视图，再右侧显示批量操作按钮（完成/删除/导出）
- **搜索筛选区**：左侧使用 XqSearchBar 组件，placeholder 为「搜索任务名称、关联客户、负责人」，宽度 240px；右侧使用 XqFilterBar 组件平铺筛选条件
- **明细内容区**：默认使用 XqDataTable 表格视图，支持列排序、行悬停、操作列固定；数据量小于等于 20 条时默认切换为 XqCardGrid 卡片视图
- **分页区**：使用 Ant Design Vue Pagination 组件，列表视图每页 12 条，卡片视图每页 8 条

#### 移动端布局

- **标题区**：顶部固定返回按钮 + 标题「我的任务」，右下角悬浮固定定位的 button 标签 class="btn-primary" 作为新建任务按钮
- **统计卡片区**：横向滚动，每个 XqKpiCard 最小宽度 120px
- **Tab 区**：顶部横向滚动，显示全部/我的/团队/逾期
- **搜索筛选区**：搜索框吸顶，宽度 100%；筛选入口在搜索右侧，点击弹出底部抽屉筛选面板
- **明细内容区**：单列卡片列表，使用 XqCardGrid 组件自定义渲染任务卡片；卡片左滑显示快捷操作（完成/编辑/删除）
- **分页区**：底部显示「加载更多」按钮，或页码「1/1 页，共 4 条」
- **手势**：下拉刷新列表，上拉加载下一页，左滑卡片显示快捷操作

### 6.2 任务详情页

#### PC 端布局

- **头部区**：使用 XqBackButton 返回列表，标题显示任务名称，右侧显示 XqStatusBadge 状态标签和 button 标签操作按钮（编辑、完成、删除、关闭）
- **基础信息区**：2 列布局显示任务编号、类型、优先级、负责人、参与人、截止时间、关联对象、创建人、创建时间
- **内容区**：使用 XqNavTabs 切换「任务概览」「跟进记录」「附件」「操作日志」
  - 任务概览：显示任务描述、子任务列表、进度条
  - 跟进记录：使用 XqTimeline 显示状态变更和评论
  - 附件：使用 Ant Design Vue Upload 组件显示附件列表
  - 操作日志：使用 XqTimeline 显示操作留痕

#### 移动端布局

- **头部区**：全屏页面，顶部固定返回按钮 + 标题，底部固定「标记完成」主按钮
- **基础信息区**：单列折叠面板，默认展开基础信息
- **内容区**：顶部页签横向滚动，内容区可垂直滚动
- **操作按钮**：底部固定主操作，次要操作收起在右上角「更多」菜单

## 八、交互设计要点

### 8.1 搜索与筛选

- **搜索框**：使用 XqSearchBar 组件，placeholder 为「搜索任务名称、关联客户、负责人」，支持拼音首字母搜索，输入 debounce 300ms 后触发查询
- **筛选条件**：
  - 优先级：全部 / 高 / 中 / 低
  - 状态：全部 / 待处理 / 进行中 / 已完成 / 已关闭 / 已逾期
  - 类型：全部 / 个人任务 / 协作任务 / 系统任务
  - 时间范围：今天 / 本周 / 本月 / 自定义
- **快捷 Tab**：全部 / 我的任务 / 团队任务 / 已逾期，切换 Tab 时保留搜索词，重置分页到第 1 页
- **筛选结果反馈**：列表顶部显示「共 N 条结果」，提供「清空筛选」按钮

### 8.2 操作反馈

- **新建任务成功**：抽屉关闭，列表顶部出现新任务，XqToast 提示「任务创建成功」
- **标记完成**：弹出 XqConfirmDialog 二次确认，确认后状态变为已完成，行内显示删除线，提示「任务已完成」
- **删除任务**：危险操作，XqConfirmDialog 提示「删除后不可恢复，是否继续」，确认后从列表移除
- **逾期预警**：已逾期任务在列表中置顶显示，状态标签为红色，截止时间显示为「逾期 N 天」
- **系统任务生成**：当客户/意向/工单触发规则时，自动创建系统任务并发送消息通知

### 8.3 空态设计

- **无数据**：使用 XqEmptyState 组件，type='empty'，标题「暂无任务」，描述「点击下方按钮创建第一条任务」，操作按钮「新建任务」
- **无搜索结果**：type='search'，标题「未找到相关任务」，描述「请尝试更换关键词或清空筛选条件」
- **无权限**：type='permission'，标题「无权查看」，描述「您没有查看该任务的权限，请联系管理员」

### 8.4 快捷操作

- **PC 端列表行**：悬停显示操作按钮，根据状态显示不同操作
  - 待处理：编辑 / 删除 / 领取
  - 进行中：更新进度 / 完成 / 转交
  - 已完成：查看 / 重启
  - 已逾期：完成 / 关闭 / 重新指派
- **移动端卡片**：左滑显示快捷操作按钮，长按弹出操作菜单

### 8.5 异常处理

- **网络错误**：列表加载失败时显示 XqEmptyState type='error'，提供「重新加载」按钮
- **表单校验错误**：必填项未填写时边框变红并显示提示文案，提交接口不被调用
- **并发冲突**：保存时检测到数据已被他人修改，提示「数据已更新，请刷新后重试」
- **越权操作**：无权限时按钮禁用或隐藏，点击后跳转无权限页面

## 十一、验收断言清单

  2. 已逾期任务置顶显示

  1. 在搜索框输入「zs」
  2. 等待 300ms debounce
- **预期结果**：
  1. 列表只显示负责人包含「张三」的任务
  2. 总条数更新为匹配数量
  3. 清空搜索后列表恢复

## 十二、关联与扩展

### 12.1 与其它模块关联

| 关联模块 | 关联点 | 说明 |
|---|---|---|
| 消息中心 | 任务创建、派发、逾期、完成时发送通知 | 使用消息中心统一推送 |
| 日历模块 | 任务的截止时间同步到日历 | 在日历中显示任务截止事件 |
| 客户 360° | 任务可关联客户，客户详情显示关联任务 | 双向跳转 |
| 意向管理 | 任务可关联意向，意向详情显示关联任务 | 支持跟进类任务 |
| 线索管理 | 任务可关联线索，线索详情显示关联任务 | 支持线索跟进任务 |
| 售后工单 | 任务可关联工单，工单详情显示关联任务 | 支持服务类任务 |
| 工作台 | 今日待办展示今日到期任务 | 工作台数据看板 |
| 应用中心 | 任务作为一级入口在侧边栏展示 | 属于平台级入口 |

### 12.2 易遗漏点

1. **逾期状态定时任务**：需要每日/每小时扫描未完成任务，判断是否逾期，并触发消息提醒
2. **系统任务生成规则**：客户拜访到期、意向保护期到期、工单 SLA 预警等场景需要自动生成任务
3. **任务进度与状态联动**：进度 100% 时是否自动标记完成，需要明确规则，建议由用户手动确认
4. **附件上传大小与类型限制**：单个文件不超过 50MB，支持图片、文档、压缩包
5. **任务转交历史留痕**：转交操作需要记录原负责人和新负责人，便于审计
6. **参与人通知机制**：参与人评论或上传附件时，负责人需要收到通知
7. **批量操作权限校验**：批量完成/删除时需要逐条校验权限，失败条数返回前端
8. **移动端键盘适配**：表单页面需要处理键盘弹出时的滚动和按钮位置
9. **任务完成后的数据联动**：完成后是否影响客户健康度、销售 KPI 等，需要后续扩展
10. **删除任务的软删除**：使用 deleted 字段标记，保留历史数据用于审计

### 12.3 待确认问题

1. 系统任务是否允许人工关闭，还是必须完成指定动作后自动关闭
2. 任务逾期后是否允许重新设置截止时间，是否需要审批
3. 是否支持任务模板和周期性任务
4. 任务完成是否需要上级确认，还是负责人自行标记即可
5. 任务与绩效目标的关联关系是否需要在本阶段实现
