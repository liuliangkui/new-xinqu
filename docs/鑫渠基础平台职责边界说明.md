# 鑫渠基础平台职责边界说明

> **文档版本**：v1.0  
> **更新日期**：2026-07-29  
> **对应原型**：《鑫渠高保真原型.html》v1.8.0  
> **文档定位**：明确鑫渠 CRM 中「后台设置」「应用配置」「流程设计器」「审批中心」四个容易混淆的基础平台入口之间的职责边界、数据关系与使用场景，避免重复设计和实现冲突。

---

## 一、总体关系

这四个入口都是**基础平台层**的前端配置/运行入口，它们共同支撑上层业务应用，但各自服务的角色和场景不同：

```
┌─────────────────────────────────────────────────────────────┐
│                      基础平台层                              │
├───────────────┬───────────────────┬─────────────────────────┤
│  组织权限平台  │   应用配置平台     │      工作流平台         │
│               │                   │                         │
│  用户/角色    │  字段/视图/流程    │   流程建模（设计时）     │
│  组织/数据范围 │  标签/权限/字典    │   流程实例（运行时）     │
│  脱敏/安全    │  版本/发布         │   审批待办（运行时）     │
│  日志审计     │                   │                         │
├───────────────┴───────────────────┴─────────────────────────┤
│   后台设置          应用配置            流程设计器/审批中心   │
│  （前端入口）      （前端入口）            （前端入口）       │
└─────────────────────────────────────────────────────────────┘
```

---

## 二、各入口职责边界

### 2.1 后台设置

| 项目 | 说明 |
|---|---|
| **所属平台** | 组织权限平台 + 系统集成平台 |
| **服务角色** | 系统管理员、安全合规管理员、组织架构管理员、IT 集成工程师 |
| **核心职责** | 租户级基础配置：组织用户、角色权限、数据字典、系统参数、日志审计、集成配置、区域保护、敏感词库、脱敏规则 |
| **设计原则** | 面向系统治理，配置结果影响整个租户或多个应用 |
| **典型操作** | 新增用户、分配角色、配置数据范围、查看操作日志、配置 ERP/OA 集成 |

**禁止事项**：
- 不在后台设置中配置某个业务应用的字段、列表列、表单布局（这些属于应用配置）。
- 不在后台设置中绘制具体审批流程（这些属于流程设计器）。

### 2.2 应用配置

| 项目 | 说明 |
|---|---|
| **所属平台** | 应用配置平台 |
| **服务角色** | 应用配置专员、业务架构师、系统管理员 |
| **核心职责** | 按业务应用维度配置：字段、视图、流程绑定、标签、权限、数据字典、版本发布 |
| **设计原则** | 面向应用装配，配置结果只影响指定应用 |
| **典型操作** | 为「意向管理」新增字段、调整列表视图列、启用审批流程、配置应用内角色权限 |

**与后台设置的区别**：
- 后台设置配置的是「全系统共享的用户、角色、字典、集成」。
- 应用配置配置的是「某个应用的字段、视图、流程绑定、权限矩阵」。

**禁止事项**：
- 不在应用配置中创建系统级角色或配置组织架构（这些属于后台设置）。
- 不在应用配置中绘制跨应用的通用流程模板（这些属于流程设计器）。

### 2.3 流程设计器

| 项目 | 说明 |
|---|---|
| **所属平台** | 工作流平台 |
| **服务角色** | 流程管理员、业务架构师、系统管理员 |
| **核心职责** | 可视化流程建模：拖拽节点、配置审批人、条件分支、字段权限、版本管理 |
| **设计原则** | 面向流程建模，定义「流程应该怎么走」 |
| **典型操作** | 创建「意向报备审批流程」、配置厂家经理复审节点、设置金额大于 50 万走财务审批 |

**与审批中心的关系**：
- 流程设计器是**设计时**工具，产出流程定义。
- 审批中心是**运行时**入口，消费流程定义产生的待办。

**禁止事项**：
- 流程设计器不处理具体单据的审批操作（这些在审批中心完成）。
- 流程设计器不配置应用字段或列表视图（这些属于应用配置）。

### 2.4 审批中心

| 项目 | 说明 |
|---|---|
| **所属平台** | 工作流平台 |
| **服务角色** | 所有需要审批或查看审批记录的角色 |
| **核心职责** | 统一审批入口：待我审批、我已审批、抄送我的、我发起的 |
| **设计原则** | 面向审批人，聚合跨业务的待办，提供统一的审批操作体验 |
| **典型操作** | 通过/驳回/转交/加签意向报备、学术活动申请、返利调整 |

**与流程设计器的关系**：
- 审批中心是工作流平台的**运行时前端**。
- 流程设计器是工作流平台的**建模时前端**。

**禁止事项**：
- 审批中心不配置流程节点或审批规则（这些属于流程设计器）。
- 审批中心不管理用户权限或组织架构（这些属于后台设置）。

    │                  │

## 四、配置层级关系

| 层级 | 配置入口 | 影响范围 | 配置示例 |
|---|---|---|---|
| 租户级 | 后台设置 | 整个租户 | 组织架构、角色体系、通用数据字典、集成配置 |
| 应用级 | 应用配置 | 指定应用 | 字段、视图、流程绑定、应用内权限、标签 |
| 流程级 | 流程设计器 | 所有引用该流程的应用 | 审批节点、条件分支、字段权限、超时提醒 |
| 运行时 | 审批中心 | 当前用户可见的待办 | 通过、驳回、转交、加签 |

## 五、常见误区澄清

| 误区 | 正确理解 |
|---|---|
| 「审批中心」是一个独立的业务应用 | 不是。审批中心是工作流平台的运行时入口，是通用能力的前端聚合。 |
| 「流程设计器」是独立系统 | 不是。流程设计器是工作流平台的建模工具，与审批中心同属一个平台。 |
| 「应用配置」可以管理用户和角色 | 不能。应用配置只管理应用内的字段、视图、流程绑定和权限矩阵；用户和角色在后台设置管理。 |
| 「后台设置」可以配置具体业务字段 | 不应该。后台设置只管理通用字典和系统参数；业务应用字段在应用配置中管理。 |
| 「区域保护」属于经销商协同应用 | 不是。区域保护是渠道协同域的业务规则，但其配置入口属于后台设置（系统级规则）。经销商协同应用只是调用这些规则。 |
| 「敏感词库」属于合规风控应用 | 不是。敏感词库是合规审计域的规则配置，配置入口属于后台设置；合规风控应用调用敏感词服务进行审计。 |

## 七、开发约束

1. **后台设置** 的接口路径建议为 `/api/v1/admin/...`。
2. **应用配置** 的接口路径建议为 `/api/v1/app-config/...`。
3. **流程设计器** 的接口路径建议为 `/api/v1/workflow/designer/...`。
4. **审批中心** 的接口路径建议为 `/api/v1/workflow/runtime/...` 或 `/api/v1/approval/...`。
5. 四个入口共享同一套用户会话与权限校验，但各自的功能权限树独立维护。
6. 工作流平台的流程定义变更必须通过应用配置平台的「流程绑定」才能被业务应用使用。
